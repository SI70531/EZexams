6.1 Background: Memory and Protection背景：記憶體與保護

In plain wordsA program on disk must first be copied into memory and become a process before it can run. The CPU can directly touch only registers and main memory. Every process must stay inside its own piece of memory, so the hardware checks every address.白話 磁碟上的程式要先搬進記憶體、變成 process 才能跑。CPU 能直接碰的只有暫存器和主記憶體。每個 process 只能待在自己那一塊記憶體裡，所以硬體會檢查每一個位址。
  • A program must be brought (from disk) into memory and placed within a process for it to be run.程式要從磁碟載入記憶體、放進一個 process 裡才能執行。
  • Main memory and registers are the only storage the CPU can access directly. The memory unit only sees a stream of addresses plus read requests, or addresses plus data and write requests.主記憶體和暫存器是 CPU 唯一能直接存取的儲存裝置。記憶體單元只看到一串「位址＋讀取要求」或「位址＋資料＋寫入要求」。
  • Register access takes one CPU clock (or less); main memory can take many cycles, causing a stall. A cache sits between main memory and the CPU registers.存取暫存器只要一個 clock（或更少）；主記憶體要很多個 cycle，會造成 stall（CPU 空等）。cache 放在主記憶體和暫存器之間。
  • Protection of memory is required to ensure correct operation.需要記憶體保護，系統才能正確運作。

Base and Limit Registers ★★基底與界限暫存器

  • A pair of base and limit registers define the logical address space of a process: base = the smallest legal physical address, limit = the size of the range.一對 base 和 limit 暫存器定義 process 的位址空間：base＝最小的合法實體位址，limit＝範圍大小。
  • The CPU must check every memory access generated in user mode to be sure it is between base and base + limit; otherwise it traps to the OS (addressing error).CPU 要檢查 user mode 產生的每一個記憶體存取，確定位址在 base 和 base + limit 之間；不然就 trap 給 OS（addressing error）。
Hardware address protection with base and limit registers: two comparisons on every user-mode access.用 base 與 limit 做硬體位址保護：每次 user mode 存取都要比兩次。

6.2 Address Binding ★★★位址綁定的三個時機

  • Addresses are represented in different ways at different stages: source code addresses are usually symbolic (e.g. variable count); the compiler binds them to relocatable addresses ("14 bytes from the beginning of this module"); the linker or loader binds those to absolute addresses (e.g. 74014).位址在不同階段長得不一樣：原始碼裡是符號（例如變數 count）；compiler 把它綁成可重定位位址（「這個模組開頭往後 14 bytes」）；linker 或 loader 再綁成絕對位址（例如 74014）。
  • Each binding maps one address space to another.每一次綁定都是把一個位址空間對應到另一個。

6.3 Logical vs. Physical Address, MMU ★★★邏輯位址、實體位址、MMU

ANSWER TEMPLATELogical address: generated by the CPU; also referred to as a virtual address. Physical address: the address seen by the memory unit. Logical and physical addresses are the same in compile-time and load-time address-binding schemes; they differ in the execution-time address-binding scheme.
中文邏輯位址：CPU 產生的位址，也叫虛擬位址。實體位址：記憶體單元看到的位址。compile time 和 load time 綁定時兩者相同；execution time 綁定時兩者不同。
  • Logical address space = the set of all logical addresses generated by a program; physical address space = the set of all physical addresses corresponding to them.邏輯位址空間＝程式產生的所有邏輯位址；實體位址空間＝它們對應的所有實體位址。
  • MMU (Memory-Management Unit): the hardware device that at run time maps virtual to physical addresses.MMU（記憶體管理單元）：執行時把虛擬位址轉成實體位址的硬體。
  • Simplest scheme: the base register is renamed the relocation register; its value is added to every address generated by a user process when it is sent to memory. The user program deals with logical addresses and never sees the real physical addresses.最簡單的做法：base register 改叫 relocation register，user process 送出的每個位址都加上它。使用者程式只看得到邏輯位址，永遠看不到真正的實體位址。
Dynamic relocation using a relocation register: 346 + 14000 = 14346.用 relocation register 做動態重定位：346 + 14000 = 14346。

6.4 Swapping ★★置換

  • A process can be swapped temporarily out of memory to a backing store and then brought back into memory for continued execution. The total physical memory space of processes can exceed physical memory.process 可以暫時被換出到 backing store，之後再換回記憶體繼續執行。所有 process 的總大小可以超過實體記憶體。
  • Backing store: a fast disk large enough to hold copies of all memory images for all users; must provide direct access to these images.Backing store：夠大的快速磁碟，能放所有使用者的記憶體映像，而且要能直接存取。
  • Roll out, roll in: a swapping variant for priority-based scheduling; a lower-priority process is swapped out so a higher-priority process can be loaded and executed.Roll out, roll in：用於優先權排班的變形；低優先權的被換出，讓高優先權的載入執行。
  • The major part of swap time is transfer time; total transfer time is directly proportional to the amount of memory swapped.換出換入的時間主要是傳輸時間，跟換的記憶體大小成正比。
  • Whether a swapped-out process must come back to the same physical addresses depends on the address-binding method (execution-time binding → it can go anywhere). Pending I/O into the process's memory is a problem.換回來要不要放同一個實體位置，看用哪種綁定（execution time 綁定就可以放別處）。process 記憶體還有進行中的 I/O 時會出問題。
  • UNIX, Linux and Windows use modified swapping: normally disabled; started when more than a threshold of memory is allocated, disabled again when demand drops below it.UNIX、Linux、Windows 用改良版：平常關閉；記憶體用量超過門檻才啟動，降到門檻以下再關閉。

6.5 Contiguous Allocation: First, Best and Worst Fit ★★★連續配置與三種 fit

  • Main memory is usually divided into two partitions: the resident OS (usually in low memory with the interrupt vector) and user processes (in high memory). Each process is contained in a single contiguous section of memory.主記憶體通常分兩區：常駐 OS（放低位址，和中斷向量在一起）與使用者 process（高位址）。每個 process 占一段連續的記憶體。
  • Relocation registers protect user processes from each other and from changing OS code and data: the base (relocation) register holds the smallest physical address; the limit register holds the range of logical addresses, and every logical address must be less than the limit.relocation register 保護 process 之間、以及 OS 的程式和資料：base（relocation）存最小實體位址；limit 存邏輯位址範圍，每個邏輯位址都要小於 limit。
  • Multiple-partition allocation with variable partition sizes: a hole is a block of available memory, holes of various sizes are scattered throughout memory. An arriving process gets memory from a hole large enough; an exiting process frees its partition and adjacent free partitions are combined. The OS keeps (a) allocated partitions and (b) free partitions (holes).多重分割配置（大小可變）：hole 是一塊可用的記憶體，大小不一、散落各處。process 來了就從夠大的 hole 切一塊；離開時釋放，相鄰的空區合併。OS 記錄 (a) 已配置區 (b) 空閒區（hole）。
ANSWER: Dynamic storage-allocation problemFirst-fit: allocate the first hole that is big enough. Best-fit: allocate the smallest hole that is big enough; must search the entire list unless it is ordered by size; produces the smallest leftover hole. Worst-fit: allocate the largest hole; must also search the entire list; produces the largest leftover hole. First-fit and best-fit are better than worst-fit in terms of speed and storage utilization.
中文First-fit：配第一個夠大的 hole。Best-fit：配最小的夠大 hole，除非按大小排序否則要掃完整串，剩下的 hole 最小。Worst-fit：配最大的 hole，也要掃完整串，剩下的 hole 最大。速度與空間利用率上，first-fit 和 best-fit 比 worst-fit 好。

6.6 Fragmentation ★★★碎片

ANSWER TEMPLATEExternal fragmentation: total memory space exists to satisfy a request, but it is not contiguous. Internal fragmentation: allocated memory may be slightly larger than requested memory; this size difference is memory internal to a partition, but not being used.
中文外部碎片：總空間夠，但不連續，所以配不出去。內部碎片：配給的比要求的稍大，多出來那塊在分割區裡面卻沒被用到。
  • 50-percent rule: first-fit analysis shows that given N allocated blocks, another 0.5N blocks are lost to fragmentation, so one third of memory may be unusable: 0.5N ÷ (N + 0.5N) = 1/3.50% 規則：first-fit 分析顯示配了 N 塊，就有 0.5N 塊因碎片浪費，所以大約三分之一記憶體可能不能用：0.5N ÷ (N + 0.5N) = 1/3。
  • Reduce external fragmentation by compaction: shuffle memory contents to place all free memory together in one large block. Compaction is possible only if relocation is dynamic and done at execution time.用壓縮（compaction）減少外部碎片：把記憶體內容搬一搬，讓空閒空間併成一大塊。只有動態重定位（execution time 綁定）才能做。
  • I/O problem during compaction: latch the job in memory while it is involved in I/O, or do I/O only into OS buffers. The backing store has the same fragmentation problems.壓縮時的 I/O 問題：做 I/O 時把工作鎖在記憶體，或 I/O 只進 OS 的緩衝區。backing store 也有同樣的碎片問題。
  • The other fix is to let the physical address space be noncontiguous: segmentation and paging.另一個解法是讓實體位址空間不必連續：segmentation 和 paging。

6.7 Segmentation ★★分段

In plain wordsSegmentation follows the user's view: a program is a collection of logical units (main program, functions, stack, symbol table, arrays …), each a segment of its own length. An address is "which segment + how far into it".白話 分段照使用者的觀點：程式是一堆邏輯單位（主程式、函式、stack、symbol table、陣列……），每個是一段，長度各不同。位址就是「第幾段＋段內多遠」。
  • Logical address = <segment-number, offset>.邏輯位址＝<段號, 位移>。
  • Segment table: each entry has a base (starting physical address of the segment) and a limit (length of the segment).Segment table：每筆有 base（段在實體記憶體的起點）和 limit（段長）。
  • STBR (segment-table base register) points to the segment table's location in memory; STLR (segment-table length register) is the number of segments; segment number s is legal if s < STLR.STBR 指向記憶體中的 segment table；STLR 是段的數量；段號 s 合法的條件是 s < STLR。
  • Protection: each entry has a validation bit (0 = illegal segment) and read / write / execute privileges. Code sharing happens at the segment level.保護：每筆有 validation bit（0＝非法段）和讀／寫／執行權限。程式碼共用以段為單位。
  • Segments vary in length, so allocation is again a dynamic storage-allocation problem (external fragmentation).段長度不一，所以配置又變成動態儲存配置問題（會有外部碎片）。
Segmentation hardware: s picks the entry, d is checked against the limit, then added to the base.分段硬體：s 選表格那一列，d 先和 limit 比，再加上 base。

6.8 Paging ★★★分頁

In plain wordsCut physical memory into equal-size frames and the program into pages of the same size. Any page can go into any free frame, so there is no external fragmentation; only the last page may be partly empty (internal fragmentation). A page table records which frame holds each page.白話 把實體記憶體切成一樣大的 frame，程式切成一樣大的 page。任何 page 都能放進任何空 frame，所以沒有外部碎片；只有最後一頁可能沒塞滿（內部碎片）。page table 記每一頁放在哪個 frame。
  • The physical address space of a process can be noncontiguous. Avoids external fragmentation and the problem of varying-sized memory chunks.process 的實體位址空間可以不連續。避免外部碎片和大小不一的問題。
  • Physical memory → fixed-size blocks called frames (size a power of 2, between 512 bytes and 16 MB); logical memory → blocks of the same size called pages. Keep track of all free frames.實體記憶體切成固定大小的 frame（2 的次方，512 bytes 到 16 MB）；邏輯記憶體切成同樣大小的 page。要記錄所有空 frame。
  • To run a program of N pages, find N free frames and load it; set up a page table to translate logical to physical addresses. The backing store is split into pages too. Still has internal fragmentation.跑 N 頁的程式就找 N 個空 frame 載入；建立 page table 做位址轉換。backing store 也切成 page。仍有內部碎片。
ANSWER: Address translation schemeThe address generated by the CPU is divided into a page number (p), used as an index into a page table which contains the base address of each page in physical memory, and a page offset (d), combined with that base address to define the physical memory address sent to the memory unit. For a logical address space of 2m and a page size of 2n, the page number is the high-order m − n bits and the offset is the low-order n bits.
中文CPU 產生的位址分成 page number（p，拿去查 page table，得到該頁在實體記憶體的起點）和 page offset（d，加在起點上得到實體位址）。邏輯位址空間 2m、頁大小 2n：高 m − n 位是頁號，低 n 位是位移。
Paging hardware: p indexes the page table to get frame f; the offset d is kept as it is.分頁硬體：用 p 查 page table 得到 frame f；位移 d 原封不動。

Paging example: n = 2, m = 4 (32-byte memory, 4-byte pages); page table: page 0 → frame 5, page 1 → frame 6, page 2 → frame 1, page 3 → frame 2.分頁範例：n = 2、m = 4（32 bytes 記憶體、每頁 4 bytes）；page table：0→5、1→6、2→1、3→2。

6.9 Page-Table Implementation: TLB and EAT ★★★page table 實作：TLB 與有效存取時間

  • The page table is kept in main memory. PTBR (page-table base register) points to it; PTLR (page-table length register) gives its size.page table 放在主記憶體。PTBR 指向它；PTLR 是它的大小。
  • Then every data / instruction access needs two memory accesses (one for the page table, one for the data), i.e. 2 × memory access time.這樣每次存取資料／指令都要兩次記憶體存取（一次查 page table、一次拿資料），時間變兩倍。
  • Fix: a special fast-lookup hardware cache called associative memory or translation look-aside buffer (TLB), searched in parallel. If p is in the TLB (hit), take the frame number from it; otherwise (miss) get it from the page table in memory and load it into the TLB for next time.解法：用一種快速查表硬體快取，叫關聯式記憶體或 TLB，可平行搜尋。p 在 TLB 裡（hit）就直接拿 frame 號；不在（miss）就去記憶體查 page table，並放進 TLB 下次用。
  • TLBs are small (64 to 1,024 entries); replacement policies must be considered; some entries can be wired down for permanent fast access.TLB 很小（64 到 1,024 筆），要考慮替換策略；有些項目可以固定（wired down）常駐。
  • ASIDs (address-space identifiers) in each TLB entry identify the process, giving address-space protection; without them the TLB must be flushed at every context switch.TLB 每筆加 ASID 標出是哪個 process，提供保護；沒有 ASID 的話，每次 context switch 都要清空 TLB。

6.10 Structure of the Page Table ★★★page table 的結構

StructureHashed page tablesSlide 55 to 56雜湊分頁表

  • Common in address spaces > 32 bits. The virtual page number is hashed into a page table; each slot holds a chain of elements hashing to the same location.常用在超過 32 位元的位址空間。把虛擬頁號雜湊到表裡；每格是一串雜湊到同一位置的元素。
  • Each element contains (1) the virtual page number, (2) the value of the mapped page frame, (3) a pointer to the next element. Virtual page numbers are compared along the chain; on a match the frame is extracted.每個元素有 (1) 虛擬頁號 (2) 對應的 frame (3) 指向下一個的指標。沿著串比對虛擬頁號，對到就取出 frame。

StructureInverted page tableSlide 57 to 58反轉分頁表

  • Rather than each process having a page table tracking all possible logical pages, track all physical pages: one entry for each real page (frame) of memory, for the whole system.不是每個 process 一張表記所有邏輯頁，而是記所有實體頁：整個系統只有一張，每個 frame 一筆。
  • Each entry holds the virtual address of the page stored in that frame plus information about the owning process (pid). A logical address is <pid, p, d>; the index i of the matching entry is the frame number.每筆記這個 frame 裡放的是哪個虛擬頁、屬於哪個 process（pid）。邏輯位址是 <pid, p, d>；對到的那一筆的索引 i 就是 frame 號。
  • Decreases the memory needed to store page tables but increases the time to search the table on each reference. Use a hash table to limit the search to one or a few entries; the TLB accelerates access.存 page table 的記憶體變少，但每次查表的時間變多。用雜湊表把搜尋限制在一兩筆；TLB 也能加速。
  • Shared memory is hard: an entry holds only one mapping of a virtual address to the shared physical address.共享記憶體很難做：一筆只能記一個虛擬位址對應到那個共享的實體位址。

7.5 Page Replacement Basics ★★★分頁替換的基本流程

7.8 Thrashing and the Working-Set Model ★★★輾轉與工作集模型

ANSWER: ThrashingIf a process does not have "enough" pages, the page-fault rate is very high: it faults to get a page, replaces an existing frame, but quickly needs the replaced frame back. 中文把資料複製在多個故障模式獨立的非揮發性媒介上並受控更新：每個邏輯區塊兩個實體區塊，先寫第一個，成功再寫第二個，第二個成功才算完成；故障後由恢復程序還原成一致狀態。三種結果：成功完成、部分失敗（只寫了部分 sector，正在寫的可能壞掉）、完全失敗（還沒開始寫，舊資料完好）。

E6 · 6Compare SCAN, C-SCAN and LOOK. Which algorithm can cause starvation, and which are reasonable defaults?

Show reference answer
ANSWERSCAN (elevator) moves the arm from one end of the disk to the other, servicing requests, then reverses at the end. C-SCAN services requests in one direction only and returns to the beginning without servicing on the return trip, giving a more uniform wait time. LOOK is SCAN that reverses at the last request instead of going to the end of the disk. SSTF can starve requests far from the head. SSTF or LOOK is a reasonable default; SCAN and C-SCAN suit systems with a heavy disk load.
中文SCAN（電梯）手臂從一端走到另一端沿路服務，到底才回頭。C-SCAN 只單向服務，到底後直接回到開頭、回程不服務，等待時間較平均。LOOK 是走到最後一個要求就回頭的 SCAN。SSTF 會讓遠的要求飢餓。預設可選 SSTF 或 LOOK；磁碟負載重時 SCAN、C-SCAN 較好。
