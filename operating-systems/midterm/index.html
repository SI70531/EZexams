1.1 OS 是什麼

Plain talkThe OS is a middleman between the user and the hardware. It manages the CPU (Central Processing Unit), memory, and disk so that programs are easy to write, the computer is easy to use, and hardware is not wasted.白話 OS 是介於「使用者」和「硬體」之間的中間人。它幫你管 CPU（Central Processing Unit，中央處理器）、memory（記憶體）、disk（硬碟），讓程式好寫、電腦好用、硬體不浪費。
ANSWER TEMPLATE — What is an OS?An operating system is a program that acts as an intermediary between a user of a computer and the computer hardware.
Goals: (1) execute user programs and make solving user problems easier; (2) make the computer system convenient to use; (3) use the computer hardware in an efficient manner.
中文作業系統是介於使用者和電腦硬體之間的「中間人」程式。目標：(1) 執行使用者程式、讓解決問題更容易；(2) 讓電腦系統方便使用；(3) 有效率地使用硬體。
  • Four components of a computer system:電腦系統四個元件：
    1. Hardware: provides the basic computing resources, namely the CPU, memory, and I/O devices.Hardware：提供最基本的計算 resource（資源），也就是 CPU、memory、I/O devices。
    2. Operating system: controls and coordinates the use of the hardware among the various application programs and users.Operating system：在各種應用程式和使用者之間，控制並協調硬體的使用。
    3. Application programs: define how the system resources are used to solve users' problems, e.g., word processor, compiler, web browser, database system, video game.Application programs：決定怎麼用系統 resource 來解決使用者的問題，例如 word processor、compiler、web browser、database system、video game。
    4. Users: people, machines, other computers.Users：人、機器、其他電腦。
Four Components of a Computer System: users get work done through application programs, and application programs use the hardware through the OS.Four Components of a Computer System：使用者透過應用程式做事，應用程式透過 OS 使用硬體。
  • What the OS does depends on the point of view:OS 在做什麼，要看從誰的角度（point of view）：
    • User point of view: users want convenience and ease of use, and do not care about resource utilization. A shared computer (e.g., a server) must keep all users satisfied; a workstation has dedicated resources but often also uses shared resources from servers; a handheld device has few resources, so the focus is usability and battery life.使用者角度（User）：使用者要的是方便、好用（convenience, ease of use），不在乎 resource 使用率。 共用的電腦（例如 server）要讓所有使用者都滿意；workstation 有專屬 resource，但也常用 server 的共用 resource；handheld（手持 device（裝置））resource 少，重點是好用和電池續航。
  • Two roles of the OS from the computer's point of view: Resource allocator (allocates resources fairly and efficiently), Control program (controls program execution to prevent errors and improper use).從電腦角度看 OS 的兩個角色：Resource allocator（分配 resource，公平又有效率）、Control program（控制程式執行，防止錯誤與不當使用）。
  • Definition of an OS: there is no universally accepted definition. "Everything the vendor ships when you order an OS" is a good approximation, but it varies widely. A more precise statement: the kernel = "the one program running at all times on the computer". Everything else is either a system program (shipped with the OS) or an application program.OS 的定義：沒有公認的定義。「你買 OS 時廠商附給你的所有東西」是個不錯的近似，但差異很大。比較精確的說法：kernel（核心）＝「the one program running at all times on the computer（電腦上一直在執行的那一個程式）」。其他東西不是 system program（跟 OS 一起出貨的），就是 application program。
  • Computer Startup: a bootstrap program is loaded at boot or reboot. It is usually stored in ROM (Read Only Memory) or EPROM (Erasable Programmable ROM), known as BIOS (Basic Input and Output System), and generally called firmware. It initializes all aspects of the system, then loads the OS kernel and starts executing it.Computer Startup（開機）：boot（開機）或重 boot 時會載入 bootstrap program（開機程式）。它通常存在 ROM（Read Only Memory）或 EPROM（Erasable Programmable ROM）裡，叫做 BIOS（Basic Input and Output System），一般稱為 firmware（韌體）（韌體）。它會初始化系統的所有部分，然後載入 OS kernel 並開始執行。

1.3 Interrupt（中斷）★★

Plain talkWhen a device finishes its work, it "rings the doorbell" to notify the CPU; that is an interrupt. The CPU pauses its current work → looks up the table (interrupt vector) to find the handler (ISR) → returns after handling. A trap / exception is an interrupt caused by software itself (e.g., divide by 0, calling a system call).白話 device 做完事，就「按門鈴」通知 CPU，這就是 interrupt。CPU 暫停手上工作 → 查表 (interrupt vector) 找到對應的處理程式 (ISR) → 處理完再回去。Trap（陷阱） / exception 是軟體自己造成的 interrupt（例如除以 0、呼叫 system call）。
ANSWER TEMPLATEAn interrupt transfers control to the interrupt service routine through the interrupt vector, which contains the addresses of all the service routines. The interrupt architecture must save the address of the interrupted instruction. A trap (exception) is a software-generated interrupt caused either by an error or a user request. An operating system is interrupt driven.
中文中斷（interrupt）透過中斷向量（interrupt vector，存放所有服務程式的位址）把控制權交給中斷服務程式（ISR）。中斷機制必須保存被中斷那條指令的位址。陷阱（trap／exception）是軟體產生的中斷，原因是錯誤或使用者請求。作業系統是靠中斷驅動的（interrupt driven）。
  • Common functions of interrupts:Interrupt 的共同功能：
    1. An interrupt transfers control to the interrupt service routine (ISR) through the interrupt vector (the interrupt vector table, which holds the addresses of all service routines).interrupt 會透過 interrupt vector（中斷向量）（中斷向量表，存著所有 service routine 的位址）把控制權交給 interrupt service routine（ISR）。
    2. The interrupt architecture must save the address of the interrupted instruction so it can return after handling.interrupt 架構必須記住被打斷的那一行指令的位址，處理完才能回去。
    3. A trap / exception is a software-generated interrupt caused by an error (e.g., divide by 0) or a user request (system call).Trap／exception 是軟體產生的 interrupt，原因是錯誤（例如除以 0）或使用者的 request（system call）。
    4. The OS is interrupt driven: it waits when there is nothing to do and acts only when an interrupt occurs.OS 是 interrupt driven（靠 interrupt 驅動）：沒事時就等，有 interrupt 才動。
  • Interrupt Handling: the OS first saves the registers and program counter (saving the CPU state), then determines which type of interrupt occurred, and finally the corresponding code segment decides what to do.Interrupt Handling（處理流程）：OS 先把 registers（暫存器） 和 program counter（程式計數器） 存起來（保存 CPU 狀態），再判斷是哪種 interrupt，最後由對應的那段程式碼決定要做什麼。
  • Determining the type of interrupt: polling (ask each in turn) or a vectored interrupt system (direct table lookup).判斷是哪種 interrupt：polling（輪詢）（輪流問）或 vectored interrupt system（直接查表）。
  • I/O flow: device → controller's local buffer → CPU moves the data to memory; the controller raises an interrupt when finished.I/O 流程：device → controller 的 local buffer → CPU 把資料搬到 memory；controller 完成時發 interrupt。
Interrupt Timeline: when the device finishes transferring data (transfer done) it raises an interrupt; the CPU pauses the user process, runs a short interrupt handler, then resumes.Interrupt Timeline：device 傳完資料（transfer done）就發 interrupt，CPU 暫停 user process（行程），跑一小段 interrupt 處理，再回去。

1.4 DMA ★★★

Plain talkWithout DMA, the CPU is interrupted for every 1 byte moved, which is a nuisance. With DMA, the device controller moves an entire block of data directly into main memory by itself, and raises only one interrupt when everything is moved. The CPU can do other things while the data is being moved. Suitable for high-speed I/O devices whose speed is close to memory speed.白話 沒有 DMA 時，資料每搬 1 byte 就要打斷 CPU 一次，CPU 會被煩死。有了 DMA，device controller 自己把一整塊（block）資料直接搬進 main memory，全部搬完才發一次 interrupt。CPU 在搬資料的期間可以做別的事。適合速度接近 memory 的高速 I/O device。
ANSWERDMA is used for high-speed I/O devices able to transmit information at close to memory speeds. The device controller transfers blocks of data from buffer storage directly to main memory without CPU intervention. Only one interrupt is generated per block, rather than one interrupt per byte.
中文DMA 用在傳輸速度接近記憶體的高速 I/O 裝置。裝置控制器（device controller）不經過 CPU，直接把整塊資料從緩衝區搬到主記憶體。每一「塊」只產生一次中斷，而不是每個 byte 一次。

1.5 Storage（儲存）

  • bit, byte, word: a bit is the smallest unit (0 or 1). A byte = 8 bits is the smallest convenient chunk for most computers; e.g., a computer usually has no instruction to "move 1 bit" but has one to "move 1 byte". A word is the native data unit of a computer architecture, made of one or more bytes; e.g., on a computer with 64-bit registers, a word is usually 64 bits (8 bytes), and many operations process one word at a time.bit、byte、word：bit 是最小單位（0 或 1）。byte = 8 bits，是大多數電腦最小的方便處理單位，例如電腦通常沒有「搬 1 個 bit」的指令，但有「搬 1 個 byte」的指令。word 是該電腦架構的原生資料單位，由一個或多個 byte 組成，例如 64-bit registers 的電腦，word 通常是 64 bits（8 bytes），很多運算一次就處理一個 word。
  • Main memory: the only large storage the CPU can access directly; random access; usually volatile (contents are lost when power is off).Main memory：CPU 唯一能直接存取的大型儲存；random access；通常 volatile（揮發性，斷電即消失）（斷電就沒）。
  • Secondary storage: an extension of main memory; large capacity, nonvolatile.Secondary storage（次要儲存）：main memory 的延伸，大容量、nonvolatile（非揮發性）。
    • Magnetic disk: rigid metal or glass platters coated with magnetic material. The surface is logically divided into circular tracks, each subdivided into sectors. The disk controller handles the logical interaction between the device and the computer.Magnetic disk：硬的金屬或玻璃碟片，表面塗磁性材料。表面邏輯上切成一圈圈 track，每圈再切成 sector。disk controller 負責 device 和電腦之間的邏輯互動。
    • Solid-state disk (SSD): faster than magnetic disk and also nonvolatile; many technologies exist and it is increasingly popular.Solid-state disk（SSD）：比 magnetic disk 快，也是 nonvolatile，技術很多種，越來越普及。
Moving-head Disk Mechanism: the platters spin around a spindle; the read-write head is mounted on an arm that moves to a track and waits for the desired sector to rotate under it.Moving-head Disk Mechanism：碟片繞轉軸轉，讀寫頭裝在讀寫臂上移到某條 track，等要的 sector 轉過來。
  • Storage hierarchy ordered by speed, cost, volatility: registers → cache → main memory → SSD → magnetic disk → optical disk → tape. The higher up, the faster, more expensive, and smaller.Storage hierarchy（儲存階層） 依 speed、cost、volatility 排列：registers → cache（快取） → main memory → SSD → magnetic disk → optical disk → tape。越上面越快、越貴、越小。
Storage-Device Hierarchy: the higher the level, the faster, more expensive, and smaller; main memory and above lose their contents when power is off (volatile).Storage-Device Hierarchy：越上層越快、越貴、容量越小；main memory 以上斷電就消失（volatile）。
  • Caching: an important principle found at many levels (hardware, OS, software). Data in use is temporarily copied from slower storage to faster storage.Caching：重要的原則，在很多層都有（硬體、OS、軟體）。把正在用的資料從慢的地方暫時複製到快的地方。
    1. First check whether the data is in the cache (faster).先查 cache（比較快）有沒有。
    2. Yes → use it directly from the cache (fast).有 → 直接從 cache 用（快）。
    3. No → first copy the data into the cache, then use it from the cache.沒有 → 先把資料複製進 cache，再從 cache 用。
    The cache is smaller than the storage being cached, so cache management is an important design problem: how large the cache is (cache size) and whom to evict when it is full (replacement policy). Main memory can also be viewed as a cache for secondary storage.cache 比被 cache 的那層小，所以 cache management 是重要的設計問題：cache 要多大（cache size）、滿了要丟掉誰（replacement policy）。main memory 也可以看成 secondary storage 的 cache。
  • Device driver: every device controller has one; it gives the kernel a uniform interface.Device driver：每個 device controller 都有，給 kernel 一個統一的介面。
  • Units: 1 KB = 210 = 1,024 ≈ 103 bytes, MB = 220 ≈ 106, GB = 230 ≈ 109, TB = 240 ≈ 1012, PB = 250 ≈ 1015. Vendors often round, saying 1 MB = 1 million bytes and 1 GB = 1 billion bytes.單位：1 KB = 210 = 1,024 ≈ 103 bytes，MB = 220 ≈ 106，GB = 230 ≈ 109，TB = 240 ≈ 1012，PB = 250 ≈ 1015。廠商常四捨五入，說 1 MB = 100 萬 bytes、1 GB = 10 億 bytes。

Increased reliability 的兩種程度：graceful degradation vs. fault tolerance ★★

Plain talkWhen a CPU in a multiprocessor system fails, can the system keep working? There are two levels:
Graceful degradation: the failed part stops working and the system keeps running, but slower. Speed is proportional to the remaining usable hardware. Example: if 1 of 10 CPUs fails, the remaining 9 continue, about 10% slower.
Fault tolerance: stronger than degradation; a failed component has no effect at all on operation, and users notice nothing. This is done by providing an extra copy of hardware (redundancy) doing the same work simultaneously, and by being able to detect, diagnose, and correct errors. Example: two CPUs execute the same job in lockstep; if one fails, the other outputs as usual.白話 多處理器系統壞掉一顆 CPU 時，還能不能繼續工作？有兩種程度：
Graceful degradation（優雅降級）：壞掉的部分不做了，系統繼續跑，但變慢。速度和剩下能用的硬體成正比。例：10 顆 CPU 壞 1 顆，剩 9 顆繼續做，大約慢 10%。
Fault tolerance（容錯）：比降級更強，壞掉一個元件完全不影響運作，使用者感覺不到。做法是多準備一份硬體（redundancy）同時做同樣的事，並能偵測、診斷、修正錯誤。例：兩顆 CPU 同步執行同一份工作，一顆壞了另一顆照常輸出。

Plain talkThe CPU has two modes: user mode (ordinary programs) and kernel mode (the OS itself). The hardware distinguishes them with a mode bit. 3.5 預測下一次 CPU burst（Exponential Averaging）★★

Why predict? SJF picks the process with the shortest next CPU burst, but the OS cannot know in advance how long the next burst will be. So it can only guess from past bursts. The assumption: the next burst should be similar to the previous ones.為什麼要預測？SJF 要選「下一次 CPU burst 最短」的 process，但 OS 不可能事先知道下一次會跑多久。所以只能用過去的 burst 來猜。這裡的假設是：下一次應該跟前幾次差不多。

公式和符號

τ(n+1) = α · t(n) + (1 − α) · τ(n) t(n) = actual length of the n-th burst (already happened) τ(n) = predicted value for the n-th burst (guessed earlier) τ(n+1) = prediction for the next burst (what we compute now) α = weight, 0 ≤ α ≤ 1, usually 1/2τ(n+1) = α · t(n) + (1 − α) · τ(n) t(n) = 第 n 次「實際」跑了多久（已經發生的事實） τ(n) = 第 n 次的「預測值」（之前猜的） τ(n+1) = 下一次的預測值（現在要算的） α = 權重，0 ≤ α ≤ 1，通常取 1/2

In plain words: new guess = a weighted mix of the most recent actual value and the previous guess. The larger α is, the more it trusts the latest actual value; the smaller α is, the more it trusts the accumulated past guesses.白話：新的猜測 = 「剛發生的實際值」和「上一次的猜測」按比例混合。α 越大，越相信最近一次的實際值；α 越小，越相信過去累積的猜測。

E8 · 5 分Distinguish user threads from kernel threads, and explain why the many-to-one model cannot run threads in parallel on a multicore system while the one-to-one model can.

看參考答案
ANSWERUser threads are managed by a user-level thread library (e.g., POSIX Pthreads, Win32 threads, Java threads) without kernel support; kernel threads are supported and managed directly by the operating system (Windows, Linux, Solaris, Mac OS X). 5.1 Deadlock 是什麼

In plain wordsTwo cars meet head-on on a narrow road and neither will back up, so both are stuck. A process uses a resource in the order request → use → release; deadlock is a group of processes each waiting for a resource held by another, and waiting forever.白話 兩台車在窄路上對開，誰都不肯退，結果兩台都動不了。Process（行程） 使用 resource（資源）的順序是 request → use → release；deadlock 就是一群 process 互相等對方手上的 resource，永遠等不到。
Thread 1: lock(first_mutex); lock(second_mutex); Thread 2: lock(second_mutex); lock(first_mutex); → T1 gets first, T2 gets second, then each waits for the other → deadlockThread 1: lock(first_mutex); lock(second_mutex); Thread 2: lock(second_mutex); lock(first_mutex); → T1 拿到 first、T2 拿到 second，接著互相等對方 → deadlock

System Model（系統模型）

  • The system consists of resources: resource types R1, R2, …, Rm, e.g. CPU (Central Processing Unit) cycles, memory space, I/O devices.系統由resource組成：resource types R1, R2, …, Rm，例如 CPU（Central Processing Unit，中央處理器） cycles、memory（記憶體） space、I/O devices。
  • Each resource type Ri has Wi instances (e.g. 2 printers → W = 2).每種 resource Ri 有 Wi 個 instances（例如 2 台印表機 → W = 2）。
  • Each process uses a resource in this order: request → use → release.每個 process 使用 resource 一定照這個順序：request（申請）→ use（使用）→ release（釋放）。

5.3 Resource-Allocation Graph（RAG）★★

  • Circle = process P; box = resource type R, dots inside = number of instances.圓圈 = process P；方框 = resource type R，裡面的點 = instance 數量。

BASIC FACTS ★★★If the graph contains no cycles → no deadlock.

5.6 Deadlock Avoidance 與 Safe State ★★★

5.1

Deadlock 是什麼

  • Resources are always used in order: request → use → release.使用 resource 一定照順序：request → use → release。
  • Deadlock: a group of processes each waiting for a resource held by another, and the wait never ends.Deadlock：一群 process 互相等對方手上的 resource，永遠等不到。
  • Example: T1 lock(first) → lock(second); T2 lock(second) → lock(first); each grabs one and they block each other.例：T1 lock(first) → lock(second)；T2 lock(second) → lock(first)，各拿一個就互卡。

When the CPU switches to another process, the system must save the state of the old process (into its PCB) and load the saved state for the new process. Context-switch time is overhead because the system does no useful work while switching.
中文CPU 換到另一個 process 時，系統要把舊 process 的狀態存進它的 PCB，再載入新 process 的狀態。內容切換的時間是額外負擔，因為切換時系統沒做有用的事。

P3. Compare preemptive and nonpreemptive scheduling.

In nonpreemptive scheduling, once the CPU is allocated to a process, the process keeps it until it terminates or switches to the waiting state. In preemptive scheduling, the CPU can be taken away from a running process (e.g., by a timer interrupt or a higher-priority arrival). Scheduling when a process switches from running to waiting or terminates is nonpreemptive; all other scheduling is preemptive.
中文不可搶奪式（nonpreemptive）：CPU 一旦給了某個 process，它會一直用到結束或進入等待狀態。可搶奪式（preemptive）：正在執行的 process 可以被搶走 CPU（例如計時器中斷或有更高優先權的 process 到達）。從 running 變 waiting 或結束時的排班是不可搶奪的，其他情況都是可搶奪的。

P4. Compare multiprogramming and timesharing.

Multiprogramming keeps several jobs in memory so the CPU always has one to execute; when one job waits for I/O, the OS switches to another job (for efficiency). Timesharing is a logical extension in which the CPU switches jobs so frequently that users can interact with each job while it is running (for interactivity, response time < 1 second).
中文多元程式把多個工作放在記憶體，讓 CPU 永遠有事做；一個工作等 I/O 時就換另一個（目的是效率）。分時是延伸：CPU 換得非常頻繁，使用者能在執行時跟每個工作互動（目的是互動性，回應時間 < 1 秒）。

P5. Explain the difference between concurrency and parallelism.P5. Explain the difference between concurrency（並行） and parallelism（平行）.

Concurrency supports more than one task making progress, e.g., a single core interleaving tasks. Parallelism means a system can perform more than one task simultaneously, which requires multiple cores.
中文並行（concurrency）是讓多個工作都有進展，例如單核心輪流執行。平行（parallelism）是真的同時執行多個工作，需要多核心。

P6. Compare shared memory and message passing.

In shared memory, cooperating processes share a region of memory and exchange data by reading and writing it; it is fast because the kernel is not involved after setup. In message passing, processes communicate through send() and receive() via the kernel without sharing variables; it is easier to implement and useful for small amounts of data and distributed systems.
中文共享記憶體：合作的 process 共用一塊記憶體，靠讀寫它交換資料；設定好之後不用經過核心，所以快。訊息傳遞：process 透過核心用 send() 和 receive() 溝通，不共用變數；比較好實作，適合少量資料和分散式系統。

P7. Compare direct and indirect communication.

In direct communication, processes must name each other explicitly (send(P, msg), receive(Q, msg)); a link is associated with exactly one pair of processes. In indirect communication, messages are sent to and received from mailboxes (ports); processes can communicate only if they share a mailbox, and a link may be associated with many processes.
中文直接通訊：process 要明確指名對方（send(P, msg)、receive(Q, msg)），一條連結只屬於一對 process。間接通訊：訊息送到信箱（mailbox／port）再從信箱收；共用同一個信箱才能通訊，一條連結可以連很多 process。

P8. What is a safe state? What is the relationship between safe, unsafe and deadlock?P8. What is a safe state（安全狀態）? What is the relationship between safe, unsafe and deadlock?

A system is in a safe state if there exists a safe sequence of all processes in which each process's remaining needs can be satisfied by the available resources plus resources held by all earlier processes. Safe state → no deadlock; unsafe state → possibility of deadlock. Deadlock states are a subset of unsafe states.
中文如果存在一個所有 process 的安全順序，讓每個 process 還需要的資源都能由「可用資源＋前面所有 process 持有的資源」滿足，系統就是安全狀態。安全 → 不會死結；不安全 → 可能死結。死結狀態是不安全狀態的子集合。

P9. How can each deadlock condition be prevented?

Mutual exclusion: not required for sharable resources (hard to deny in general). Hold and wait: a process must request all its resources before execution, or only when it holds none. No preemption: if a request cannot be granted, the process releases all resources it holds. Circular wait: impose a total ordering of resource types and request them in increasing order.
中文互斥：可共享的資源不需要（但一般很難否定這個條件）。持有並等待：執行前一次要齊所有資源，或手上沒資源時才能要。不可搶奪：要求的資源拿不到時，就放掉手上所有資源。循環等待：把資源類型排好順序，只能照遞增順序要資源。

P10. Explain multilevel feedback queue scheduling with an example.

A process can move between queues. Example: three queues — Q0 (RR, quantum 8 ms), Q1 (RR, quantum 16 ms), Q2 (FCFS). A new job enters Q0; if it does not finish in 8 ms it moves to Q1; if it still does not finish in 16 more ms it is moved to Q2. Short jobs finish quickly; aging can be implemented by moving a process up.
中文process 可以在佇列間移動。例子：三個佇列：Q0（RR，配額 8 ms）、Q1（RR，配額 16 ms）、Q2（FCFS）。新工作進 Q0，8 ms 內沒做完就降到 Q1；再 16 ms 還沒做完就降到 Q2。短工作很快做完；把 process 往上移就能實作老化（aging）。

P11. What is the bootstrap program?P11. What is the bootstrap program（開機程式）?

The bootstrap program is loaded at power-up or reboot. It is stored in ROM or EPROM (firmware), initializes all aspects of the system, and loads the operating-system kernel and starts its execution.
中文開機程式（bootstrap program）在開機或重開機時載入，存在 ROM 或 EPROM（韌體 firmware）裡，負責初始化系統各部分，並載入作業系統核心（kernel）開始執行。

P12. What is the difference between fork() and exec()?

fork() creates a new process that is a duplicate of the parent. exec() is used after fork() to replace the process's memory space with a new program.
中文fork() 建立一個和父 process 一模一樣的新 process。exec() 在 fork() 之後用，把 process 的記憶體換成新的程式。
