Ch1 Introduction

operating system（作業系統）是什麼、interrupt（中斷）、DMA（Direct Memory Access，直接記憶體存取）、儲存階層、dual mode。讀完後做最下面的選擇題。

1.1 OS 是什麼

白話OS 是介於「使用者」和「硬體」之間的中間人。它幫你管 CPU（Central Processing Unit，中央處理器）、memory（記憶體）、disk（硬碟），讓程式好寫、電腦好用、硬體不浪費。
ANSWER TEMPLATE — What is an OS?An operating system is a program that acts as an intermediary between a user of a computer and the computer hardware.
Goals: (1) execute user programs and make solving user problems easier; (2) make the computer system convenient to use; (3) use the computer hardware in an efficient manner.
中文作業系統是介於使用者和電腦硬體之間的「中間人」程式。目標：(1) 執行使用者程式、讓解決問題更容易；(2) 讓電腦系統方便使用；(3) 有效率地使用硬體。
  • 電腦系統四個元件：Hardware（CPU、memory、I/O）→ Operating system → Application programs → Users。
  • 從電腦角度看 OS 的兩個角色：Resource（資源） allocator（分配 resource，公平又有效率）、Control program（控制程式執行，防止錯誤與不當使用）。
  • Kernel（核心）＝「電腦上一直在執行的那一個程式」。其他是 system program 或 application program。
  • Bootstrap program（開機程式）：boot（開機）時載入，存在 ROM／EPROM（稱 firmware），負責初始化系統並載入 kernel。

ANSWERControl Unit (CU), Arithmetic and Logic Unit (ALU), and Registers.
中文控制單元（Control Unit, CU）、算術邏輯單元（ALU）和暫存器（Registers）。

1.3 Interrupt（中斷）★★

白話device（裝置）做完事，就「按門鈴」通知 CPU，這就是 interrupt。CPU 暫停手上工作 → 查表 (interrupt vector) 找到對應的處理程式 (ISR) → 處理完再回去。Trap（陷阱） / exception 是軟體自己造成的 interrupt（例如除以 0、呼叫 system call）。
ANSWER TEMPLATEAn interrupt transfers control to the interrupt service routine through the interrupt vector, which contains the addresses of all the service routines. The interrupt architecture must save the address of the interrupted instruction. A trap (exception) is a software-generated interrupt caused either by an error or a user request. An operating system is interrupt driven.
中文中斷（interrupt）透過中斷向量（interrupt vector，存放所有服務程式的位址）把控制權交給中斷服務程式（ISR）。中斷機制必須保存被中斷那條指令的位址。陷阱（trap／exception）是軟體產生的中斷，原因是錯誤或使用者請求。作業系統是靠中斷驅動的（interrupt driven）。
  • 處理 interrupt 時 OS 會保存 CPU 狀態（registers（暫存器）、program counter）。
  • 判斷是哪種 interrupt：polling（輪詢）（輪流問）或 vectored interrupt system（直接查表）。
  • I/O 流程：device → controller 的 local buffer → CPU 把資料搬到 memory；controller 完成時發 interrupt。

1.4 DMA ★★★

ANSWERDMA is used for high-speed I/O devices able to transmit information at close to memory speeds. The device controller transfers blocks of data from buffer storage directly to main memory without CPU intervention. Only one interrupt is generated per block, rather than one interrupt per byte.
中文DMA 用在傳輸速度接近記憶體的高速 I/O 裝置。裝置控制器（device controller）不經過 CPU，直接把整塊資料從緩衝區搬到主記憶體。每一「塊」只產生一次中斷，而不是每個 byte 一次。

1.5 Storage（儲存）

  • Main memory（主記憶體）：CPU 唯一能直接存取的大型儲存；random access；通常 volatile（揮發性，斷電即消失）（斷電就沒）。
  • Secondary storage（次要儲存）：main memory 的延伸，大容量、nonvolatile（非揮發性）。例：magnetic disk（分 track → sector）、SSD（比 disk 快）。
  • Storage hierarchy（儲存階層） 依 speed、cost、volatility 排列：registers → cache（快取） → main memory → SSD → magnetic disk → optical disk → tape。越上面越快、越貴、越小。
  • Caching：把常用資料從慢的地方暫時複製到快的地方；先查 cache，有就直接用，沒有就複製進 cache。設計重點：cache size 和 replacement policy。
  • Device driver：每個 device controller（裝置控制器） 都有，給 kernel 一個統一的介面。
  • 單位：1 KB = 210 bytes，MB = 220，GB = 230，TB = 240，PB = 250。1 byte = 8 bits。

1.6 Computer-System Architecture

ANSWER TEMPLATE — Advantages of multiprocessor systems(1) Increased throughput; (2) Economy of scale; (3) Increased reliability (graceful degradation or fault tolerance).
中文多處理器系統的優點：(1) 提高吞吐量（throughput）；(2) 規模經濟（共用周邊、電源，比較省）；(3) 提高可靠度（一顆壞了還能降級運作 graceful degradation，或容錯 fault tolerance）。
  • Multiprocessor（多處理器） 又叫 parallel systems / tightly-coupled systems。
  • 兩種：Asymmetric multiprocessing（有主從，一個 CPU 分派工作）、Symmetric multiprocessing (SMP)（每個 CPU 地位相同，都做所有工作）。
  • Multicore（多核心）：一顆晶片多個 core（核心）。UMA／NUMA 是 memory 存取速度一不一致的差別。
  • Clustered systems（叢集系統）：多台電腦一起工作，通常透過 SAN 共用儲存，提供 high availability。Asymmetric clustering：一台 hot-standby 待命；Symmetric clustering：多台都跑應用並互相監控。

Increased reliability 的兩種程度：graceful degradation vs. fault tolerance ★★

白話多處理器系統壞掉一顆 CPU 時，還能不能繼續工作？有兩種程度：
Graceful degradation（優雅降級）：壞掉的部分不做了，系統繼續跑，但變慢。速度和剩下能用的硬體成正比。例：10 顆 CPU 壞 1 顆，剩 9 顆繼續做，大約慢 10%。
Fault tolerance（容錯）：比降級更強，壞掉一個元件完全不影響運作，使用者感覺不到。做法是多準備一份硬體（redundancy）同時做同樣的事，並能偵測、診斷、修正錯誤。例：兩顆 CPU 同步執行同一份工作，一顆壞了另一顆照常輸出。
壞掉一個元件後關鍵字
Graceful degradation繼續服務，效能下降continue providing service proportional to the surviving hardware
Fault tolerance繼續服務，效能不變continue operation despite failure；需要 redundancy／duplication
ANSWER TEMPLATE — Graceful degradation / Fault toleranceGraceful degradation is the ability to continue providing service proportional to the level of surviving hardware. Fault tolerance goes beyond graceful degradation: a fault-tolerant system can suffer a failure of any single component and still continue operation, which requires a mechanism to allow the failure to be detected, diagnosed, and, if possible, corrected.
中文優雅降級（graceful degradation）：依照剩下還能用的硬體多寡，繼續提供相應程度的服務。容錯（fault tolerance）比降級更進一步：任何單一元件故障，系統都能繼續運作，需要能偵測、診斷、並盡可能修正錯誤的機制。
分辨口訣題目說「變慢但還能跑」→ graceful degradation。說「完全不受影響、有備援」→ fault tolerance。

1.7 Multiprogramming（多元程式） vs. Timesharing（分時） ★★

白話Multiprogramming：memory 放好幾個工作，一個去等 I/O，CPU 馬上換另一個做 → CPU 永遠有事做（為了效率）。
Timesharing (multitasking)：CPU 切換得超快，每個使用者都覺得電腦只為他服務 → 為了互動，response time（回應時間） < 1 秒。
ANSWER TEMPLATEMultiprogramming organizes jobs (code and data) so the CPU always has one to execute; when a job has to wait (for I/O, for example), the OS switches to another job.
Timesharing (multitasking) is a logical extension in which the CPU switches jobs so frequently that users can interact with each job while it is running (response time < 1 second).
中文多元程式（multiprogramming）把多個工作放在記憶體，讓 CPU 永遠有事做；某個工作要等（例如等 I/O）時，OS 就切到另一個。分時（timesharing／multitasking）是延伸：CPU 切換得非常頻繁，使用者可以在程式執行時跟它互動（回應時間 < 1 秒）。
  • 相關名詞：多個工作同時 ready → CPU scheduling（排班）；memory 放不下 → swapping（置換）；process（行程） 不必全部在 memory → virtual memory。

1.8 Dual-mode（雙模式） Operation ＆ Timer ★★

白話CPU 有兩種模式：user mode（使用者模式）（一般程式）和 kernel mode（核心模式）（OS 自己）。硬體用一個 mode bit（模式位元） 區分。危險的指令（privileged instructions）只有 kernel mode 能執行。程式要請 OS 幫忙就呼叫 system call（系統呼叫） → 切到 kernel mode → 做完切回 user mode。
Timer：定時鬧鐘，防止某個程式無窮迴圈霸佔 CPU，時間到就產生 interrupt 讓 OS 拿回控制權。
ANSWER TEMPLATEDual-mode operation (user mode and kernel mode) allows the OS to protect itself and other system components. A mode bit is provided by hardware to distinguish whether the system is running user code or kernel code. Some instructions are privileged and only executable in kernel mode. A system call changes the mode to kernel; return from the call resets it to user.
A timer is used to prevent an infinite loop / a process hogging resources: it generates an interrupt after a specific period so the OS can regain control.
中文雙模式（使用者模式 user mode／核心模式 kernel mode）讓 OS 保護自己和其他元件。硬體提供模式位元（mode bit）來分辨現在跑的是使用者程式還是核心程式。部分指令是特權指令（privileged），只能在核心模式執行。系統呼叫（system call）會切到核心模式，返回時切回使用者模式。計時器（timer）用來防止無窮迴圈或某個 process 霸佔資源：時間到就發中斷，讓 OS 拿回控制權。

2.4 Context Switch（內容切換） ★★

ANSWER TEMPLATEWhen the CPU switches to another process, the system must save the state of the old process and load the saved state for the new process via a context switch. 中文CPU 換到另一個 process 時，系統要先保存舊 process 的狀態，再載入新 process 的狀態，這叫內容切換（context switch）。process 的狀態記在 PCB 裡。切換時間是額外負擔（overhead），切換期間系統沒做任何有用的事。

3.1 基本概念

3.5 預測下一次 CPU burst（Exponential Averaging）★★

為什麼要預測？SJF 要選「下一次 CPU burst 最短」的 process，但 OS 不可能事先知道下一次會跑多久。所以只能用過去的 burst 來猜。這裡的假設是：下一次應該跟前幾次差不多。

公式和符號

τ(n+1) = α · t(n) + (1 − α) · τ(n) t(n) = 第 n 次「實際」跑了多久（已經發生的事實） τ(n) = 第 n 次的「預測值」（之前猜的） τ(n+1) = 下一次的預測值（現在要算的） α = 權重，0 ≤ α ≤ 1，通常取 1/2

白話：新的猜測 = 「剛發生的實際值」和「上一次的猜測」按比例混合。α 越大，越相信最近一次的實際值；α 越小，越相信過去累積的猜測。

α 的兩個極端（考試愛考）

α公式變成意思
0τ(n+1) = τ(n)Recent history does not count：最近發生什麼都不管，永遠用舊的猜測
1τ(n+1) = t(n)Only the actual last CPU burst counts：只看上一次實際跑多久
1/2τ(n+1) = (t(n) + τ(n)) / 2最近的實際值和過去的歷史各占一半

為什麼叫「指數」平均：把公式展開

第 1 步：原式 τ(n+1) = α·t(n) + (1−α)·τ(n) 第 2 步：τ(n) 也用公式換掉 τ(n) = α·t(n−1) + (1−α)·τ(n−1) 代進去 τ(n+1) = α·t(n) + (1−α)·α·t(n−1) + (1−α)²·τ(n−1) 第 3 步：τ(n−1) 再換掉 τ(n+1) = α·t(n) + (1−α)·α·t(n−1) + (1−α)²·α·t(n−2) + (1−α)³·τ(n−2) 第 4 步：一直換到 τ(0)，得到一般式： τ(n+1) = α·t(n) + (1−α)·α·t(n−1) + (1−α)²·α·t(n−2) + … + (1−α)^j·α·t(n−j) + … + (1−α)^(n+1)·τ(0)

例：α = ½ 時，權重依序是 ½、¼、⅛、1/16…，最後 τ(0) 剩 (½)^(n+1)。每往前一次，權重就多乘一個 (1−α)。因為 α 和 (1−α) 都 ≤ 1，越舊的 burst 權重越小，而且是指數變小。所以最近的 burst 影響最大，很久以前的幾乎不算。

Multilevel Queue (MLQ)

  • Ready queue 分成好幾條，例如 foreground (interactive) 用 RR、background (batch) 用 FCFS。

  • Process 可以在 queue 之間移動，所以可以實作 aging。
  • 設計參數：queue 數量、每條 queue 的演算法、何時升級、何時降級、新 process 進哪條 queue。
MLFQ 例子：短工作在 Q0 就做完（優先），長工作慢慢沉到 Q2。

5.1 Deadlock 是什麼

白話兩台車在窄路上對開，誰都不肯退，結果兩台都動不了。Process（行程） 使用 resource（資源）的順序是 request → use → release；deadlock 就是一群 process 互相等對方手上的 resource，永遠等不到。
Thread 1: lock(first_mutex); lock(second_mutex); Thread 2: lock(second_mutex); lock(first_mutex); → T1 拿到 first、T2 拿到 second，接著互相等對方 → deadlock

5.2 四個必要條件 ★★★

條件英文定義（申論題用）白話
Mutual exclusion（互斥）Only one process at a time can use a resource.resource 一次只能一個人用
Hold and wait（持有並等待）A process holding at least one resource is waiting to acquire additional resources held by other processes.手上拿著，還在等別的
No preemption（不可搶奪）A resource can be released only voluntarily by the process holding it, after that process has completed its task.不能硬搶
Circular wait（循環等待）There exists a set {P0, P1, …, Pn} of waiting processes such that P0 waits for P1, P1 waits for P2, …, Pn waits for P0.等待形成一個圈
ANSWERDeadlock can arise if four conditions hold simultaneously: mutual exclusion, hold and wait, no preemption, and circular wait.
中文四個條件同時成立才可能死結：互斥（mutual exclusion）、持有並等待（hold and wait）、不可搶奪（no preemption）、循環等待（circular wait）。

5.3 Resource-Allocation Graph（RAG）★★

  • 圓圈 = process P；方框 = resource type R，裡面的點 = instance 數量。
  • Request edge（請求邊）：P → R（P 在要 R）。
  • Assignment edge（分配邊）：R → P（R 已分配給 P）。
  • Claim edge（宣告邊）（avoidance（避免） 用）：P ⇢ R 虛線，表示「將來可能會要」。
BASIC FACTS ★★★If the graph contains no cycles → no deadlock.
If the graph contains a cycle → (1) if only one instance per resource type, then deadlock; (2) if several instances per resource type, possibility of deadlock.
中文圖裡沒有環 → 沒有死結。圖裡有環 → (1) 每種資源只有一個 instance：一定死結；(2) 每種資源有多個 instance：可能死結。
P1→R1→P2→R2→P1 形成 cycle，每種 resource 只有 1 個 → deadlock。

5.4 處理 Deadlock 的三種方法 ★★

ANSWER TEMPLATE(1) Ensure that the system will never enter a deadlock state (deadlock prevention or avoidance).
(2) Allow the system to enter a deadlock state and then recover (detection and recovery).
(3) Ignore the problem and pretend that deadlocks never occur in the system; used by most operating systems.
中文處理死結的三種方法：(1) 保證系統永遠不進入死結（預防 prevention 或避免 avoidance）；(2) 允許進入死結，再偵測並恢復（detection and recovery）；(3) 不理它，假裝死結不會發生，大部分作業系統都這樣做。

5.5 Deadlock Prevention（破壞四條件之一）★★

破壞哪個做法缺點／備註
Mutual exclusion可共用的 resource（如 read-only files）就不需要 mutual exclusion。很難用來 prevention，因為有些 resource 本來就不能共用。
Hold and wait開始前一次要齊所有 resource；或手上沒有 resource 時才能要。Low resource utilization（使用率）；可能 starvation（飢餓）。
No preemption如果要不到新 resource，就把手上所有 resource 都 release（釋放），等新舊 resource 都拿得到才重新開始。—
Circular wait替所有 resource 編號 (total ordering)，只能依遞增順序申請。最常用、最實際。

5.6 Deadlock Avoidance 與 Safe State ★★★

白話Avoidance＝事先知道每個 process 最多會要多少 resource (Max)，每次分配前先模擬：「給了之後，還找得到一個順序讓大家都做完嗎？」找得到＝safe，才給。
ANSWER TEMPLATE — Safe stateA system is in a safe state if there exists a sequence <P1, P2, …, Pn> of ALL the processes such that for each Pi, the resources that Pi can still request can be satisfied by the currently available resources plus the resources held by all Pj, with j < i.
If a system is in a safe state → no deadlocks. If a system is in an unsafe state → possibility of deadlock. Avoidance → ensure that a system will never enter an unsafe state.
中文安全狀態（safe state）：存在一個包含「所有」process 的順序 <P1, P2, …, Pn>，讓每個 Pi 還要的資源，都能被「目前可用的資源＋排在它前面所有 Pj 持有的資源」滿足。安全狀態 → 不會死結；不安全狀態 → 可能死結。避免（avoidance）就是確保系統永遠不進入不安全狀態。
Deadlock ⊂ unsafe。Unsafe 不一定 deadlock，但有可能。

5.7 Banker's Algorithm 計算 SOP ★★★（配分最重的大題）

資料結構（n 個 process，m 種資源） Available[m]: number of available instances of each resource type.
Max[n×m]: maximum demand of each process.
Allocation[n×m]: number of instances currently allocated to each process.
Need[n×m]: remaining need. Need = Max − Allocation.
中文Available[m]：每種資源目前可用的數量。Max[n×m]：每個 process 最多需要多少。Allocation[n×m]：每個 process 目前分到多少。Need[n×m]：還需要多少。Need = Max − Allocation。
Safety Algorithm 白話版（考試照這樣寫）
  1. 算 Need = Max − Allocation（每一格相減）。
  2. Work = Available。所有 Finish = false。
  3. 找一個還沒完成、而且 Need ≤ Work（每一種 resource 都要 ≤）的 process。
  4. 找到 → 假裝它做完：Work = Work + 它的 Allocation（還回的是 Allocation，不是 Need！），Finish = true，回第 3 步。
  5. 全部都 Finish → safe，寫出順序；中途卡住 → unsafe。

Resource-Request Algorithm（某 process 提出 request 能不能給？）

三關檢查
  1. Request ≤ Need？否 → error（超過它宣告的最大需求）。

5.8 Deadlock Detection ★★

  • Single instance：用 wait-for graph（等待圖）（只有 process 節點，Pi → Pj 表示 Pi 在等 Pj）。定期找 cycle，有 cycle 就有 deadlock。找 cycle 需要 O(n2)。
  • Several instances：跟 Banker's 的 safety algorithm 幾乎一樣，差別是：
    • 用 Request（目前的 request（請求））取代 Need。
    • 一開始 Allocation 全為 0 的 process 直接 Finish = true。
    • 最後 Finish[i] == false 的 Pi 就是 deadlocked。複雜度 O(m × n2)。

5.9 Recovery（回復） from Deadlock ★

Process termination

  • Abort all deadlocked processes；或
  • Abort one process at a time until the deadlock cycle is eliminated。
  • 選誰的考量：priority（優先權）、已算多久／還要多久、用了多少 resource、還需要多少 resource、要 terminate（終止）幾個、interactive 還是 batch。

Resource preemption

  • Selecting a victim（犧牲者） – minimize cost。
  • Rollback（回滾） – return to some safe state, restart process from that state。
  • Starvation – same process may always be picked as victim; include number of rollbacks in cost factor。

申論題型（describe / explain / compare）

P1. What is a Process Control Block (PCB)? What information does it contain?

A PCB (task control block) stores information associated with each process: process state, program counter, CPU registers, CPU-scheduling information, memory-management information, accounting information, and I/O status information.
中文PCB（Process Control Block，行程控制區塊；又叫 task control block）存每個 process 的資訊：process 狀態、程式計數器、CPU 暫存器、CPU 排班資訊、記憶體管理資訊、帳務資訊、I/O 狀態資訊。

P2. What is a context switch（內容切換）? Why is it overhead?

When the CPU switches to another process, the system must save the state of the old process (into its PCB) and load the saved state for the new process. Context-switch time is overhead because the system does no useful work while switching.
中文CPU 換到另一個 process 時，系統要把舊 process 的狀態存進它的 PCB，再載入新 process 的狀態。內容切換的時間是額外負擔，因為切換時系統沒做有用的事。

P3. Compare preemptive and nonpreemptive scheduling.

In nonpreemptive scheduling, once the CPU is allocated to a process, the process keeps it until it terminates or switches to the waiting state. In preemptive scheduling, the CPU can be taken away from a running process (e.g., by a timer interrupt or a higher-priority arrival). Scheduling when a process switches from running to waiting or terminates is nonpreemptive; all other scheduling is preemptive.
中文不可搶奪式（nonpreemptive）：CPU 一旦給了某個 process，它會一直用到結束或進入等待狀態。可搶奪式（preemptive）：正在執行的 process 可以被搶走 CPU（例如計時器中斷或有更高優先權的 process 到達）。從 running 變 waiting 或結束時的排班是不可搶奪的，其他情況都是可搶奪的。

P4. Compare multiprogramming and timesharing.

Multiprogramming keeps several jobs in memory so the CPU always has one to execute; when one job waits for I/O, the OS switches to another job (for efficiency). Timesharing is a logical extension in which the CPU switches jobs so frequently that users can interact with each job while it is running (for interactivity, response time < 1 second).
中文多元程式把多個工作放在記憶體，讓 CPU 永遠有事做；一個工作等 I/O 時就換另一個（目的是效率）。分時是延伸：CPU 換得非常頻繁，使用者能在執行時跟每個工作互動（目的是互動性，回應時間 < 1 秒）。

P5. Explain the difference between concurrency（並行） and parallelism（平行）.

Concurrency supports more than one task making progress, e.g., a single core interleaving tasks. Parallelism means a system can perform more than one task simultaneously, which requires multiple cores.
中文並行（concurrency）是讓多個工作都有進展，例如單核心輪流執行。平行（parallelism）是真的同時執行多個工作，需要多核心。

P6. Compare shared memory and message passing.

In shared memory, cooperating processes share a region of memory and exchange data by reading and writing it; it is fast because the kernel is not involved after setup. In message passing, processes communicate through send() and receive() via the kernel without sharing variables; it is easier to implement and useful for small amounts of data and distributed systems.
中文共享記憶體：合作的 process 共用一塊記憶體，靠讀寫它交換資料；設定好之後不用經過核心，所以快。訊息傳遞：process 透過核心用 send() 和 receive() 溝通，不共用變數；比較好實作，適合少量資料和分散式系統。

P7. Compare direct and indirect communication.

In direct communication, processes must name each other explicitly (send(P, msg), receive(Q, msg)); a link is associated with exactly one pair of processes. In indirect communication, messages are sent to and received from mailboxes (ports); processes can communicate only if they share a mailbox, and a link may be associated with many processes.
中文直接通訊：process 要明確指名對方（send(P, msg)、receive(Q, msg)），一條連結只屬於一對 process。間接通訊：訊息送到信箱（mailbox／port）再從信箱收；共用同一個信箱才能通訊，一條連結可以連很多 process。

P8. What is a safe state（安全狀態）? What is the relationship between safe, unsafe and deadlock?

A system is in a safe state if there exists a safe sequence of all processes in which each process's remaining needs can be satisfied by the available resources plus resources held by all earlier processes. Safe state → no deadlock; unsafe state → possibility of deadlock. Deadlock states are a subset of unsafe states.
中文如果存在一個所有 process 的安全順序，讓每個 process 還需要的資源都能由「可用資源＋前面所有 process 持有的資源」滿足，系統就是安全狀態。安全 → 不會死結；不安全 → 可能死結。死結狀態是不安全狀態的子集合。

P9. How can each deadlock condition be prevented?

Mutual exclusion: not required for sharable resources (hard to deny in general). Hold and wait: a process must request all its resources before execution, or only when it holds none. No preemption: if a request cannot be granted, the process releases all resources it holds. Circular wait: impose a total ordering of resource types and request them in increasing order.
中文互斥：可共享的資源不需要（但一般很難否定這個條件）。持有並等待：執行前一次要齊所有資源，或手上沒資源時才能要。不可搶奪：要求的資源拿不到時，就放掉手上所有資源。循環等待：把資源類型排好順序，只能照遞增順序要資源。

P10. Explain multilevel feedback queue scheduling with an example.

A process can move between queues. Example: three queues — Q0 (RR, quantum 8 ms), Q1 (RR, quantum 16 ms), Q2 (FCFS). A new job enters Q0; if it does not finish in 8 ms it moves to Q1; if it still does not finish in 16 more ms it is moved to Q2. Short jobs finish quickly; aging can be implemented by moving a process up.
中文process 可以在佇列間移動。例子：三個佇列：Q0（RR，配額 8 ms）、Q1（RR，配額 16 ms）、Q2（FCFS）。新工作進 Q0，8 ms 內沒做完就降到 Q1；再 16 ms 還沒做完就降到 Q2。短工作很快做完；把 process 往上移就能實作老化（aging）。

P11. What is the bootstrap program（開機程式）?

The bootstrap program is loaded at power-up or reboot. It is stored in ROM or EPROM (firmware), initializes all aspects of the system, and loads the operating-system kernel and starts its execution.
中文開機程式（bootstrap program）在開機或重開機時載入，存在 ROM 或 EPROM（韌體 firmware）裡，負責初始化系統各部分，並載入作業系統核心（kernel）開始執行。

P12. What is the difference between fork() and exec()?

fork() creates a new process that is a duplicate of the parent. exec() is used after fork() to replace the process's memory space with a new program.
中文fork() 建立一個和父 process 一模一樣的新 process。exec() 在 fork() 之後用，把 process 的記憶體換成新的程式。
