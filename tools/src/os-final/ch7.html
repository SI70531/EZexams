7.1 Background: Virtual Memory ★★背景：虛擬記憶體

In plain wordsA program rarely needs all of its code at once (error handling, rare routines, oversized arrays). Virtual memory keeps only the needed part in memory, so a program can be larger than physical memory and more programs fit at the same time.白話 程式很少同時用到全部程式碼（錯誤處理、罕用的 routine、開太大的陣列）。虛擬記憶體只把需要的部分放進記憶體，所以程式可以比實體記憶體還大，同時也能放更多程式。
ANSWER: Virtual memoryVirtual memory is the separation of user logical memory from physical memory. Only part of the program needs to be in memory for execution, so the logical address space can be much larger than the physical address space. It allows address spaces to be shared by several processes and allows more efficient process creation. It can be implemented via demand paging or demand segmentation.
中文虛擬記憶體把使用者的邏輯記憶體和實體記憶體分開。只要部分程式在記憶體就能執行，所以邏輯位址空間可以遠大於實體位址空間。可讓多個 process 共用位址空間、讓 process 建立更有效率。實作方式：demand paging 或 demand segmentation。
  • Benefits of running a partially loaded program: not constrained by physical memory; more programs run concurrently (higher CPU utilization and throughput); less I/O needed to load or swap processes.只載入部分就能跑的好處：不受實體記憶體大小限制；能同時跑更多程式（CPU 使用率與 throughput 提高）；載入或換出 process 需要的 I/O 較少。
  • Virtual address space: stack grows down from the top, heap grows up; the hole between them is unused until needed (a sparse address space). System libraries are shared by mapping them into the virtual address space; shared memory maps pages read-write; pages can be shared during fork(), speeding process creation.虛擬位址空間：stack 從上往下長、heap 從下往上長，中間的洞要用時才配（稀疏位址空間）。系統函式庫靠映射到虛擬位址空間共用；共享記憶體把頁以可讀寫映射；fork() 時可共用頁，加快建立 process。

7.2 Demand Paging ★★★需求分頁

  • Bring a page into memory only when it is needed: less I/O, less memory, faster response, more users.需要時才把頁載入：I/O 少、記憶體少、反應快、可服務更多使用者。
  • Page is needed → reference it: invalid reference → abort; not in memory → bring it into memory.需要某頁 → 參考它：非法參考 → 終止；不在記憶體 → 載入。
  • Lazy swapper: never swaps a page into memory unless it will be needed. A swapper that deals with pages is a pager.Lazy swapper：不需要就絕不換入。以「頁」為單位的 swapper 叫 pager。
  • Valid–invalid bit in each page-table entry: v = in memory (memory resident), i = not in memory (or illegal). Initially all entries are i. If the bit is i during translation → page fault.page table 每筆有 valid–invalid bit：v＝在記憶體，i＝不在記憶體（或非法）。一開始全是 i。轉換時遇到 i → page fault。
  • Pure demand paging: start a process with no pages in memory; the very first instruction faults. One instruction may touch several pages (several faults), but locality of reference keeps this rare.純需求分頁：process 啟動時記憶體裡一頁都沒有，第一個指令就 fault。一個指令可能碰到好幾頁（好幾次 fault），但參考區域性讓這種情況很少。
  • Hardware support needed: page table with valid–invalid bit; secondary memory (swap device with swap space); instruction restart.需要的硬體支援：有 valid–invalid bit 的 page table；次級儲存（有 swap space 的 swap device）；指令重新執行。

Steps in Handling a Page Fault ★★★處理 page fault 的步驟

ANSWER TEMPLATE(1) The first reference to a page not in memory traps to the operating system (page fault). (2) The OS looks at another table to decide: invalid reference → abort; just not in memory → continue. (3) Get an empty frame. (4) Swap the page into the frame via a scheduled disk operation. (5) Reset the tables to indicate the page is now in memory; set the validation bit = v. (6) Restart the instruction that caused the page fault.
中文(1) 第一次參考不在記憶體的頁 → trap 給 OS（page fault）。(2) OS 查另一張表：非法參考就終止；只是不在記憶體就繼續。(3) 找一個空 frame。(4) 排一次磁碟操作把頁讀進 frame。(5) 更新表格，標示這頁已在記憶體，valid bit 設成 v。(6) 重新執行造成 page fault 的那個指令。
Steps in handling a page fault, in order ① to ⑥.處理 page fault 的步驟，依 ① 到 ⑥ 的順序。
The full 12 stages from the slides (for "performance" questions)投影片完整 12 個階段（考效能時用）
  1. Trap to the operating system.
  2. Save the user registers and process state.
  3. Determine that the interrupt was a page fault.
  4. Check that the page reference was legal and determine the location of the page on the disk.
  5. Issue a read from the disk to a free frame: wait in the device queue, wait for seek and/or latency, begin the transfer.
  6. While waiting, allocate the CPU to some other user.
  7. Receive an interrupt from the disk I/O subsystem (I/O completed).

7.3 Performance of Demand Paging ★★★需求分頁的效能

FORMULAPage-fault rate 0 ≤ p ≤ 1 (p = 0: no faults; p = 1: every reference faults).
EAT = (1 − p) × memory access + p × (page-fault overhead + swap page out + swap page in + restart overhead)
中文page fault 機率 p。沒 fault 就只花一次記憶體存取；fault 就要加上處理 fault、換出、換入、重新執行的時間。
memory access = 200 ns, page-fault service time = 8 ms = 8,000,000 ns EAT = (1 − p) × 200 + p × 8,000,000 = 200 + p × 7,999,800 (ns) p = 1/1,000: EAT = 200 + 7,999.8 = 8,199.8 ns ≈ 8.2 µs → slowdown by a factor of 8,199.8 / 200 ≈ 40 degradation < 10%: 220 > 200 + 7,999,800 × p 20 > 7,999,800 × p p < 0.0000025 → fewer than 1 fault in 400,000 accesses記憶體存取 200 ns、page fault 服務時間 8 ms = 8,000,000 ns EAT = (1 − p) × 200 + p × 8,000,000 = 200 + p × 7,999,800（ns） p = 1/1,000：EAT = 200 + 7,999.8 = 8,199.8 ns ≈ 8.2 µs → 慢了約 8,199.8 / 200 ≈ 40 倍 要求變慢 < 10%：220 > 200 + 7,999,800 × p 20 > 7,999,800 × p p < 0.0000025 → 每 400,000 次存取不到 1 次 fault
Common deductionConvert units first: 8 ms = 8,000,000 ns. Mixing ms and ns is the most common mistake.常見扣分 先統一單位：8 ms = 8,000,000 ns。ms 和 ns 混用是最常見的錯。
  • Optimizations: copy the whole process image to swap space at load time, then page in and out of swap space (older BSD UNIX); or demand-page from the program binary on disk and discard rather than page out when freeing a frame, checking whether it is dirty (Solaris, current BSD).最佳化：載入時把整個 process 映像先複製到 swap space，之後都在 swap space 換進換出（舊 BSD UNIX）；或直接從磁碟上的執行檔需求分頁，釋放 frame 時沒改過就丟掉不寫回（先看 dirty）（Solaris、現在的 BSD）。

7.4 Copy-on-Write ★★寫入時複製

ANSWERCopy-on-Write (COW) allows both parent and child processes to initially share the same pages in memory. If either process modifies a shared page, only then is the page copied. COW allows more efficient process creation as only modified pages are copied.
中文COW 讓父子 process 一開始共用相同的頁；任一方要修改某個共用頁時，才把那頁複製一份。只複製被改的頁，所以建立 process 更有效率。
  • Free pages are allocated from a pool of zero-fill-on-demand pages (zeroed first so the new owner cannot read old data).空頁從 zero-fill-on-demand 頁池配出（先清成 0，新主人才看不到舊資料）。
  • vfork(): the parent is suspended and the child uses the parent's address space (not copy-on-write); designed for a child that calls exec() right away. Very efficient.vfork()：父 process 暫停，子 process 直接用父的位址空間；設計給馬上呼叫 exec() 的子 process。非常有效率。
Copy-on-write: A and B stay shared; only when process 1 modifies C does it get its own copy.寫入時複製：A、B 仍共用；process 1 改 C 時才複製一份給它。

7.5 Page Replacement Basics ★★★分頁替換的基本流程

  • When there is no free frame (all used by process pages, kernel, I/O buffers), page replacement finds some page in memory that is not really in use and pages it out. Goal: an algorithm that gives the minimum number of page faults. The same page may be brought in several times.沒有空 frame 時（都被 process、kernel、I/O 緩衝區用掉），分頁替換找一個沒在用的頁換出去。目標：page fault 次數最少。同一頁可能被載入好幾次。
  • Use the modify (dirty) bit to reduce overhead: only modified pages are written back to disk.用 modify（dirty）bit 減少負擔：只有改過的頁才要寫回磁碟。
  • Page replacement completes the separation between logical and physical memory: a large virtual memory on a smaller physical memory.分頁替換讓邏輯與實體記憶體完全分開：小的實體記憶體上可以提供很大的虛擬記憶體。
ANSWER: Basic page replacement(1) Find the location of the desired page on disk. (2) Find a free frame: if there is one, use it; if not, use a page-replacement algorithm to select a victim frame, and write the victim to disk if it is dirty. (3) Bring the desired page into the (newly) free frame; update the page and frame tables. (4) Continue the process by restarting the instruction that caused the trap. Note: there are now potentially 2 page transfers per page fault, increasing EAT.
中文(1) 找到所需頁在磁碟的位置。(2) 找空 frame：有就用；沒有就用替換演算法選 victim，dirty 的話寫回磁碟。(3) 把頁讀進空出來的 frame，更新 page table 和 frame table。(4) 重新執行造成 trap 的指令。注意：一次 page fault 可能要傳兩頁，EAT 變大。
  • Frame-allocation algorithm decides how many frames each process gets; page-replacement algorithm decides which frame to replace.frame 分配演算法決定每個 process 拿幾個 frame；分頁替換演算法決定換掉哪個 frame。
  • Evaluate an algorithm by running it on a reference string (page numbers only, not full addresses) and counting page faults. A repeated access to the same page does not fault. More frames normally means fewer faults.評估方法：拿一串 reference string（只有頁號）跑，數 page fault。連續參考同一頁不會 fault。frame 越多通常 fault 越少。

CounterEvery page-table entry has a counter; on every reference copy the clock into it. To replace, find the smallest counter.每筆有一個 counter；每次參考把時鐘值抄進去。要換時找最小的 counter。A search through the table is needed.要搜尋整張表。

Approx.Reference bit and second-chance (clock)Slide 41 to 42參考位元與第二次機會（時鐘）

  • True LRU needs special hardware and is still slow, so approximate it with a reference bit: one bit per page, initially 0, set to 1 by hardware when the page is referenced. Replace any page with bit 0 (if one exists); but we do not know the order.真正的 LRU 要特殊硬體而且慢，所以用參考位元近似：每頁一個 bit，一開始 0，被參考時硬體設成 1。換掉任一個 bit 為 0 的頁；但不知道先後順序。
  • Second-chance algorithm: basically FIFO plus the reference bit, arranged as a circular queue with a clock hand. If the page to be replaced has reference bit 0 → replace it. If 1 → set it to 0, leave the page in memory (a second chance) and move on to the next page under the same rules.第二次機會演算法：FIFO 加上參考位元，排成環狀佇列，用時鐘指針掃。指到的頁 bit 是 0 → 換掉；是 1 → 清成 0、留在記憶體（給第二次機會），再看下一頁，規則一樣。
  • If every bit is 1, the hand goes all the way round and it degenerates into FIFO.如果全部都是 1，指針會繞一整圈，退化成 FIFO。
Clock algorithm: the hand clears 1-bits as it passes and stops at the first page whose bit is 0.時鐘演算法：指針經過時把 1 清成 0，停在第一個 bit 為 0 的頁。

OtherCounting algorithms: LFU and MFUSlide 44計數型：LFU、MFU

  • Keep a counter of the number of references made to each page.每頁記一個被參考次數的計數器。
  • LFU (Least Frequently Used): replace the page with the smallest count.LFU（最不常用）：換掉次數最少的頁。

OtherPage-buffering algorithmsSlide 45分頁緩衝

  • Always keep a pool of free frames, so a frame is available when needed instead of being found at fault time: read the page into a free frame, then select a victim to evict and add it to the free pool; evict the victim when convenient.永遠保留一個空 frame 池，fault 時就有現成的 frame：先把頁讀進空 frame，再選 victim 加回空池，方便時才真的換出。
  • Possibly keep a list of modified pages and write them to the backing store when it is idle, setting them to non-dirty.也可以記一份被改過的頁，backing store 閒著時先寫回，設成不 dirty。
  • Possibly keep the free frames' contents intact and remember what is in them: if a page is referenced again before reuse, no disk load is needed. Reduces the penalty of picking the wrong victim.也可以讓空 frame 的內容保持原樣並記住裡面是哪頁：重新用到之前又被參考，就不用再從磁碟載入。可降低選錯 victim 的代價。

7.7 Allocation of Frames ★★frame 的分配

  • Each process needs a minimum number of frames; the maximum is the total frames in the system. Two major schemes: fixed allocation and priority allocation.每個 process 至少要最低數量的 frame；最多是系統的總 frame 數。兩大類：固定分配、優先權分配。
  • Equal allocation: e.g. 100 frames (after the OS) and 5 processes → 20 frames each; keep some as a free-frame buffer pool.平均分配：例如 100 個 frame（扣掉 OS）、5 個 process → 每個 20 個；可留一些當空 frame 池。
  • Proportional allocation: allocate according to process size: ai = (si ÷ S) × m, where S = Σ si, m = total frames. Dynamic as the degree of multiprogramming and process sizes change.按比例分配：依 process 大小分：ai = (si ÷ S) × m，S = 所有 si 總和，m = 總 frame 數。會隨多元程式程度與 process 大小變動。
m = 64, s1 = 10, s2 = 127 → S = 137 a1 = 10 / 137 × 64 ≈ 4.67 → about 5 frames a2 = 127 / 137 × 64 ≈ 59.3 → about 59 framesm = 64、s1 = 10、s2 = 127 → S = 137 a1 = 10 / 137 × 64 ≈ 4.67 → 約 5 個 frame a2 = 127 / 137 × 64 ≈ 59.3 → 約 59 個 frame
  • Priority allocation: proportional allocation using priorities rather than size. When Pi faults, either replace one of its own frames or a frame of a process with a lower priority.優先權分配：按優先權而不是大小來比例分配。Pi 發生 fault 時，換掉自己的 frame，或換掉優先權較低的 process 的 frame。

7.8 Thrashing and the Working-Set Model ★★★輾轉與工作集模型

ANSWER: ThrashingIf a process does not have "enough" pages, the page-fault rate is very high: it faults to get a page, replaces an existing frame, but quickly needs the replaced frame back. This leads to low CPU utilization; the operating system thinks it needs to increase the degree of multiprogramming and adds another process, which makes it worse. Thrashing ≡ a process is busy swapping pages in and out (more time paging than executing).
中文process 的頁「不夠」時 page fault 率很高：fault 拿一頁、換掉一個 frame，馬上又需要剛被換掉的。結果 CPU 使用率很低；OS 以為要提高多元程式程度，又加 process 進來，更糟。Thrashing＝process 忙著換頁（花在換頁的時間比執行還多）。
Thrashing: past some degree of multiprogramming, CPU utilization drops sharply.Thrashing：多元程式程度超過某點，CPU 使用率急降。
  • Why does demand paging work? The locality model: a process migrates from one locality (set of pages used together) to another; localities may overlap.為什麼需求分頁可行？區域性模型：process 從一個 locality（一起被用的一組頁）移到另一個；locality 可能重疊。
  • Why does thrashing occur? Σ size of localities > total memory size. Limit the effects by using local or priority page replacement.為什麼會 thrashing？所有 locality 大小總和 > 記憶體總量。用區域替換或優先權替換可以限制影響。

Working-Set Model工作集模型

  • Δ ≡ working-set window: a fixed number of page references (e.g. 10,000 instructions).Δ＝工作集視窗：固定數量的頁參考（例如 10,000 個指令）。
  • WSSi (working set of Pi) = total number of pages referenced in the most recent Δ (varies in time). Δ too small → will not cover the entire locality; Δ too large → covers several localities; Δ = ∞ → covers the entire program.WSSi（Pi 的工作集）＝最近 Δ 次參考裡用到的不同頁數（會隨時間變）。Δ 太小 → 蓋不住整個 locality；Δ 太大 → 蓋到好幾個 locality；Δ = ∞ → 整個程式。
  • D = Σ WSSi = total demand frames (an approximation of locality). If D > m (total frames) → thrashing. Policy: if D > m, suspend or swap out one of the processes.D = Σ WSSi＝總需求 frame 數（近似 locality）。D > m（總 frame 數）→ thrashing。對策：D > m 時暫停或換出某個 process。
Δ = 10, page references: … 2 6 1 5 7 7 7 7 5 1 | 6 2 3 4 1 2 3 4 4 4 3 4 3 4 4 4 1 3 2 3 4 4 4 3 4 4 4 … at t1: WS(t1) = {1, 2, 5, 6, 7} WSS = 5 at t2: WS(t2) = {3, 4} WSS = 2Δ = 10，頁參考： … 2 6 1 5 7 7 7 7 5 1 | 6 2 3 4 1 2 3 4 4 4 3 4 3 4 4 4 1 3 2 3 4 4 4 3 4 4 4 … t1 時：WS(t1) = {1, 2, 5, 6, 7} WSS = 5 t2 時：WS(t2) = {3, 4} WSS = 2
  • Keeping track of the working set: approximate with an interval timer + a reference bit. Example Δ = 10,000, timer interrupt every 5,000 time units, keep 2 bits per page in memory; on each interrupt copy the reference bits and reset them to 0; if any bit = 1 the page is in the working set. Not completely accurate (we cannot tell when in the 5,000 units the reference happened); improvement: 10 bits and an interrupt every 1,000 units.追蹤工作集：用定時器＋參考位元近似。例如 Δ = 10,000、每 5,000 單位中斷一次、每頁在記憶體裡留 2 bits；每次中斷把參考位元複製下來再清成 0；只要有一個 bit 是 1 就算在工作集裡。不完全準（不知道是 5,000 單位內的哪個時間被參考）；改良：10 bits、每 1,000 單位中斷。
  • Page-fault frequency (PFF): a more direct approach. Establish an acceptable fault-rate range and use local replacement: if the actual rate is too low, the process loses a frame; if too high, it gains a frame.Page-fault frequency（PFF）：比較直接。訂一個可接受的 fault 率範圍、用區域替換：太低就拿走一個 frame；太高就多給一個 frame。

7.9 Allocating Kernel Memory ★★核心記憶體配置

  • Kernel memory is treated differently from user memory: often allocated from a free-memory pool; the kernel requests structures of varying sizes; some kernel memory must be physically contiguous (e.g. for device I/O).核心記憶體和使用者記憶體分開處理：常從空閒記憶體池配；核心要的結構大小不一；有些必須實體連續（例如給裝置 I/O）。
Buddy system夥伴系統Slab allocatorslab 配置器
Idea做法Allocates from a fixed-size segment of physically contiguous pages using a power-of-2 allocator: a request is rounded up to the next power of 2; a chunk too big is split into two buddies of the next-lower power of 2 until a suitable size exists.從一段實體連續的固定大小記憶體配，用 2 的次方配置器：要求往上取到 2 的次方；太大的塊對半切成兩個 buddy，一直切到大小合適。A slab is one or more physically contiguous pages; a cache consists of one or more slabs, one cache per unique kernel data structure, filled with objects (instances of that structure) marked free or used. A full slab → allocate from an empty slab; no empty slab → allocate a new slab.slab＝一或多個實體連續頁；cache＝一或多個 slab，每種核心資料結構一個 cache，裡面放這種結構的 object，標成 free 或 used。slab 滿了 → 從空 slab 配；沒有空 slab → 再配一個新 slab。
Pros優點Quickly coalesce unused buddies into a larger chunk.很快就能把沒用的 buddy 合併成大塊。No fragmentation; fast memory-request satisfaction.沒有碎片；要求很快被滿足。
Cons缺點Fragmentation (internal: rounding up).碎片（往上取整造成的內部碎片）。—
Buddy system: a 21 KB request on a 256 KB chunk splits 256 → 128 → 64 → 32 and takes one 32 KB buddy.夥伴系統：256 KB 上要 21 KB，切成 256 → 128 → 64 → 32，拿一塊 32 KB（浪費 11 KB）。

7.10 Other Considerations ★★其他考量

Issue議題Key points重點
PrepagingReduce the many page faults at process startup by bringing in all or some pages before they are referenced. If s pages are prepaged and a fraction α of them is used, compare the cost of the s × α saved faults with the cost of prepaging s × (1 − α) unnecessary pages: α near 0 → prepaging loses; α near 1 → prepaging wins.process 剛啟動時 fault 很多，所以事先載入全部或部分會用到的頁。預載 s 頁、其中 α 比例真的用到：比較省下的 s × α 次 fault 與白載的 s × (1 − α) 頁成本。α 接近 0 → 預載划不來；α 接近 1 → 預載划算。
Page sizeMust consider fragmentation, page-table size, resolution, I/O overhead, number of page faults, locality, TLB size and effectiveness. Always a power of 2, usually 212 (4,096 bytes) to 222 (4,194,304 bytes); on average growing over time.要考慮碎片、page table 大小、解析度、I/O 負擔、page fault 數、區域性、TLB 大小與效率。一定是 2 的次方，通常 212（4,096 bytes）到 222（4,194,304 bytes）；整體愈來愈大。
TLB reachTLB reach = TLB size × page size, the memory accessible from the TLB. Ideally each process's working set is in the TLB, otherwise there are many faults. Increase the page size (but more fragmentation) or provide multiple page sizes (large pages only for apps that need them).TLB reach = TLB 筆數 × 頁大小，靠 TLB 就能存取的記憶體量。最好每個 process 的工作集都在 TLB 裡，不然 fault 很多。可加大頁（但碎片變多）或提供多種頁大小（需要的程式才用大頁）。
Program structureint data[128][128], each row stored in one page. Looping column by column (for j … for i … data[i][j] = 0) touches a new page on every access: 128 × 128 = 16,384 faults. Looping row by row (for i … for j …): 128 faults.int data[128][128]，每一列放一頁。一欄一欄掃（for j … for i …）每次都換頁：128 × 128 = 16,384 次 fault。一列一列掃（for i … for j …）：128 次。
I/O interlockPages used for copying a file from a device must be locked in memory so they are not selected for eviction by page replacement.正在跟裝置做 I/O 的頁必須鎖在記憶體裡，不能被替換演算法選走。
Chapter summarySummary 本章總結
  • Virtual memory separates logical from physical memory, so only part of a program must be in memory; it is implemented by demand paging (load a page only when it is referenced; an i bit causes a page fault).虛擬記憶體把邏輯和實體記憶體分開，只要部分程式在記憶體；用需求分頁實作（被參考才載入；碰到 i bit 就 page fault）。
  • Page fault: trap → check legal → get a free frame → read the page in → set v → restart the instruction. EAT = (1 − p) × ma + p × fault service time; p must be tiny.Page fault：trap → 檢查合法 → 找空 frame → 讀頁 → 設成 v → 重新執行指令。EAT = (1 − p) × ma + p × 服務時間；p 要非常小。
  • Copy-on-write lets parent and child share pages until one writes, making fork() cheap.寫入時複製讓父子共用頁到有人寫入為止，fork() 變便宜。
  • Page replacement: FIFO (Belady's anomaly), OPT (fewest faults, needs the future), LRU (counter or stack), approximations with reference bits (second chance / clock, enhanced with the modify bit), LFU / MFU, page buffering. The dirty bit avoids writing clean pages back.分頁替換：FIFO（有 Belady 異常）、OPT（fault 最少、要知道未來）、LRU（counter 或 stack）、用參考位元近似（第二次機會／時鐘、再加 modify bit 的加強版）、LFU／MFU、分頁緩衝。dirty bit 讓沒改的頁不用寫回。
  • Frames are allocated equally, proportionally (ai = si/S × m) or by priority; replacement is global or local.frame 用平均、按比例（ai = si/S × m）或按優先權分配；替換分全域或區域。
  • Thrashing happens when Σ locality sizes > memory; the working-set model (D = Σ WSSi > m → suspend a process) and PFF control it. Kernel memory uses the buddy system or the slab allocator.所有 locality 總和 > 記憶體時發生 thrashing；用工作集模型（D = Σ WSSi > m → 暫停一個 process）和 PFF 控制。核心記憶體用夥伴系統或 slab 配置器。
Common trap易錯點
  • The first few references always fault (the frames start empty); count them.一開始 frame 是空的，前幾次參考一定 fault，要算進去。
  • FIFO evicts the page that arrived earliest; LRU evicts the page used least recently. A hit updates LRU's order but not FIFO's.FIFO 換掉最早進來的；LRU 換掉最久沒用的。命中會更新 LRU 的順序，但不會改 FIFO 的順序。
  • Belady's anomaly happens with FIFO, never with LRU or OPT (stack algorithms).Belady 異常出現在 FIFO，LRU 和 OPT（stack algorithm）不會。
  • Thrashing → CPU utilization goes down; adding more processes makes it worse, not better.Thrashing → CPU 使用率下降；再加 process 只會更糟。
  • Page-fault EAT: convert ms to ns before adding (8 ms = 8,000,000 ns).page fault 的 EAT：先把 ms 換成 ns 再算（8 ms = 8,000,000 ns）。
  • PFF: rate too low → take away a frame; too high → give a frame. MFU replaces the page with the largest count.PFF：fault 率太低 → 拿走 frame；太高 → 多給 frame。MFU 換掉次數最多的頁。
