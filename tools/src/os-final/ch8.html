8.1 Magnetic Disks ★★★磁碟

In plain wordsA disk is a stack of spinning platters with an arm of read-write heads. To read a block the arm first moves to the right track (seek), then waits for the sector to spin under the head (rotational latency), then transfers the data.白話 磁碟是一疊旋轉的盤片加一支讀寫頭手臂。讀一塊資料要先把手臂移到對的磁軌（seek），再等那個 sector 轉到讀寫頭下（rotational latency），最後傳資料。
Moving-head disk mechanism: platters, tracks, the cylinder formed by one track on each platter, and the arm of heads.移動式讀寫頭磁碟：盤片、磁軌、各盤片同一磁軌組成的 cylinder，以及讀寫頭手臂。
  • Drives rotate 60 to 250 times per second. Transfer rate = rate at which data flow between drive and computer.每秒轉 60 到 250 圈。傳輸率＝磁碟與電腦之間資料流動的速率。
  • Positioning time (random-access time) = seek time (move the arm to the desired cylinder) + rotational latency (time for the desired sector to rotate under the head).定位時間（隨機存取時間）＝seek time（手臂移到目標 cylinder）＋ rotational latency（目標 sector 轉到讀寫頭下的時間）。
  • Head crash: the head touches the disk surface; that's bad. Disks can be removable.Head crash：讀寫頭碰到盤面，很糟。磁碟可以是可移除的。
  • A drive attaches through an I/O bus (EIDE, ATA, SATA, USB, Fibre Channel, SCSI, SAS, FireWire). The host controller in the computer uses the bus to talk to the disk controller built into the drive or storage array.磁碟透過 I/O bus（EIDE、ATA、SATA、USB、Fibre Channel、SCSI、SAS、FireWire）連接。電腦端的 host controller 經 bus 跟磁碟裡（或儲存陣列裡）的 disk controller 溝通。
  • Typical figures: platters 0.85" to 14" (commonly 3.5", 2.5", 1.8"); 30 GB to 3 TB per drive; theoretical transfer rate 6 Gb/s, effective about 1 Gb/s; seek time 3 to 12 ms (9 ms common for desktop drives).常見數字：盤片 0.85" 到 14"（常見 3.5"、2.5"、1.8"）；每台 30 GB 到 3 TB；理論傳輸率 6 Gb/s、實際約 1 Gb/s；seek time 3 到 12 ms（桌機常見 9 ms）。
FORMULASAverage latency = ½ × one rotation = ½ × 60 ÷ RPM seconds.
Access latency = average access time = average seek time + average latency.
Average I/O time = average access time + (amount to transfer ÷ transfer rate) + controller overhead.
中文平均旋轉延遲＝轉半圈的時間＝½ × 60 ÷ RPM 秒。存取延遲＝平均 seek time＋平均旋轉延遲。平均 I/O 時間＝平均存取時間＋（資料量 ÷ 傳輸率）＋控制器負擔。
4 KB block, 7200 RPM, average seek 5 ms, 1 Gb/s transfer, 0.1 ms controller overhead one rotation = 60 / 7200 s = 8.33 ms → average latency = 4.17 ms transfer = 4 KB / 1 Gb/s = 4 / 131072 s ≈ 0.03 ms average I/O = 5 + 4.17 + 0.03 + 0.1 ≈ 9.30 ms (the slide writes the transfer as 0.12 ms and gets 9.39 ms)4 KB、7200 RPM、平均 seek 5 ms、傳輸率 1 Gb/s、控制器負擔 0.1 ms 轉一圈 = 60 / 7200 秒 = 8.33 ms → 平均旋轉延遲 = 4.17 ms 傳輸 = 4 KB / 1 Gb/s = 4 / 131072 秒 ≈ 0.03 ms 平均 I/O = 5 + 4.17 + 0.03 + 0.1 ≈ 9.30 ms （投影片把傳輸寫成 0.12 ms，得到 9.39 ms）

On the exam, write every step (seek + latency + transfer + overhead); the method earns the points.投影片數字的說明 1 Gb/s = 230 bits/s = 131,072 KB/s，所以 4 KB 約 0.03 ms。投影片寫的「0.12 ms」和它自己的 4/131072 對不起來。考試時每一步（seek＋latency＋傳輸＋overhead）都寫出來，方法才是得分重點。

8.2 Disk Structure ★★磁碟結構

  • Disk drives are addressed as large 1-dimensional arrays of logical blocks; the logical block is the smallest unit of transfer. Low-level formatting creates logical blocks on the physical media.磁碟被當成一個很大的一維邏輯區塊陣列來定址；邏輯區塊是最小的傳輸單位。低階格式化在實體媒介上建立邏輯區塊。
  • The array is mapped into the sectors sequentially: sector 0 is the first sector of the first track on the outermost cylinder; mapping proceeds through that track, then the rest of the tracks in that cylinder, then the rest of the cylinders from outermost to innermost.這個陣列依序對應到 sector：sector 0 是最外圈 cylinder 第一條磁軌的第一個 sector；先走完那條磁軌，再走同一 cylinder 的其他磁軌，再從外往內走其他 cylinder。
  • Logical-to-physical translation should be easy, except for bad sectors and a non-constant number of sectors per track (with constant angular velocity).邏輯轉實體應該很簡單，但有壞軌，而且每條磁軌的 sector 數不一定相同（constant angular velocity）。

8.4 Disk Scheduling ★★★磁碟排程

  • The OS must use the hardware efficiently: for disks this means a fast access time and high disk bandwidth. Minimize seek time; seek time ≈ seek distance.OS 要有效使用硬體：對磁碟就是存取時間要快、磁碟頻寬要高。要讓 seek time 最小；seek time ≈ seek distance。
  • Disk bandwidth = total number of bytes transferred ÷ total time between the first request for service and the completion of the last transfer.磁碟頻寬＝傳輸的總 bytes ÷（從第一個要求到最後一次傳輸完成的總時間）。
  • I/O requests come from the OS, system processes and user processes; each includes input or output mode, disk address, memory address and number of sectors. The OS keeps a queue of requests per disk; an idle disk serves a request at once, a busy disk makes work queue. Optimization only makes sense when a queue exists.I/O 要求來自 OS、系統 process、使用者 process；每個包含讀或寫、磁碟位址、記憶體位址、sector 數。OS 為每個磁碟維護要求佇列；磁碟閒著就馬上做，忙就排隊。只有有佇列時排程才有意義。

Every example uses cylinders 0 to 199, request queue 98, 183, 37, 122, 14, 124, 65, 67 and the head starting at 53.範例都用 cylinder 0 到 199，要求佇列 98, 183, 37, 122, 14, 124, 65, 67，讀寫頭從 53 開始。

Common deductionAt 67 the nearest request is 37 (distance 30), not 98 (distance 31). Check both sides at every step. SSTF is not optimal: 53 → 37 → 14 → 65 → … gives 208.常見扣分 在 67 時最近的是 37（距離 30），不是 98（距離 31）。每一步都要比兩邊。SSTF 不是最佳：53 → 37 → 14 → 65 → … 只要 208。

SweepSCAN (elevator algorithm)Slide 24 to 25電梯演算法

The arm starts at one end of the disk and moves toward the other end, servicing requests until it gets to the end of the disk, where the head movement is reversed and servicing continues. If requests are uniformly dense, the largest density is at the other end and those requests wait the longest.手臂從磁碟一端往另一端移，沿路服務要求，一直走到磁碟的盡頭才回頭，回程繼續服務。若要求平均分布，回頭時另一端累積的最多，它們等最久。

head moving toward 0: 53 → 37 → 14 → 0 → 65 → 67 → 98 → 122 → 124 → 183 (53 − 0) + (183 − 0) = 53 + 183 = 236 cylinders讀寫頭往 0 的方向： 53 → 37 → 14 → 0 → 65 → 67 → 98 → 122 → 124 → 183 (53 − 0) + (183 − 0) = 53 + 183 = 236 個 cylinder
The slide says 208The slide's SCAN figure reports 208, which is what you get if the arm turns at 14 instead of going to 0, i.e. LOOK. Strict SCAN goes to the end (0) and gives 236. On the exam, state the direction and whether the arm goes to the end, then show the sum.投影片寫 208 投影片 SCAN 那張圖寫 208，那是手臂在 14 就回頭（沒走到 0）的結果，也就是 LOOK。嚴格的 SCAN 要走到盡頭 0，結果是 236。考試時先寫方向、有沒有走到底，再列加總。

SweepC-SCAN (Circular SCAN)Slide 26 to 27環狀掃描

Provides a more uniform wait time than SCAN. The head moves from one end to the other servicing requests; when it reaches the other end it immediately returns to the beginning without servicing any requests on the return trip. Treats the cylinders as a circular list that wraps from the last cylinder to the first.等待時間比 SCAN 更平均。讀寫頭從一端往另一端移、沿路服務；到底之後立刻回到開頭，回程不服務任何要求。把 cylinder 當成環狀串列，從最後一個接回第一個。

head moving toward 199: 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 ⇒ 0 → 14 → 37 servicing sweep: 199 − 53 = 146 return jump: 199 − 0 = 199 then: 37 − 0 = 37 total = 146 + 199 + 37 = 382 cylinders (183 if the return jump is not counted)讀寫頭往 199 的方向： 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 ⇒ 0 → 14 → 37 服務那一趟：199 − 53 = 146 回程跳回： 199 − 0 = 199 接著： 37 − 0 = 37 總共 = 146 + 199 + 37 = 382（不算回程就是 183）

LOOK is a version of SCAN and C-LOOK a version of C-SCAN: the arm only goes as far as the last request in each direction, then reverses immediately, without first going all the way to the end of the disk.LOOK 是 SCAN 的版本、C-LOOK 是 C-SCAN 的版本：手臂每個方向只走到最後一個要求就立刻回頭，不必先走到磁碟盡頭。

ChoiceSelecting a disk-scheduling algorithmSlide 30怎麼選

  • SSTF is common and has a natural appeal.SSTF 很常見、直覺。
  • SCAN and C-SCAN perform better for systems that place a heavy load on the disk: less starvation.磁碟負載很重時 SCAN 和 C-SCAN 表現較好：比較不會飢餓。
  • Performance depends on the number and types of requests, which can be influenced by the file-allocation method and metadata layout.效能取決於要求的數量與種類，而這又受檔案配置方式和 metadata 擺放影響。
  • The disk-scheduling algorithm should be written as a separate module of the OS so it can be replaced if necessary. Either SSTF or LOOK is a reasonable default.磁碟排程應寫成 OS 的獨立模組，必要時可以換掉。預設用 SSTF 或 LOOK 都合理。

8.5 RAID Structure ★★★RAID 結構

ANSWER: RAIDRAID (redundant array of inexpensive / independent disks) uses multiple disk drives to provide reliability via redundancy. Disk striping uses a group of disks as one storage unit to improve performance; mirroring and parity store redundant data to improve reliability. RAID is arranged into six different levels.
中文RAID（容錯式磁碟陣列）用多顆磁碟靠冗餘提供可靠性。striping（分散寫入）把一組磁碟當一個儲存單位以提升效能；mirroring（鏡像）和 parity（同位）存冗餘資料以提升可靠性。RAID 分成六個等級。
  • Redundancy increases the mean time to failure. Mean time to repair = exposure time when another failure could cause data loss. Mean time to data loss is based on both.冗餘提高平均故障間隔。平均修復時間＝這段時間內再壞一顆就會掉資料。平均資料遺失時間由這兩者決定。
  • Frequently combined with NVRAM to improve write performance.常搭配 NVRAM 提升寫入效能。
mirrored pair, each disk MTTF = 100,000 h, MTTR = 10 h, failures independent mean time to data loss = MTTF² / (2 × MTTR) = 100,000² / (2 × 10) = 500 × 10^6 hours ≈ 57,000 years兩顆鏡像、每顆 MTTF = 100,000 小時、MTTR = 10 小時、各自獨立故障 平均資料遺失時間 = MTTF² / (2 × MTTR) = 100,000² / (2 × 10) = 500 × 10^6 小時 ≈ 57,000 年
  • Disk striping: bit-level (bit i to disk i) or block-level (block i to disk i).Striping：bit 層級（第 i 個 bit 到第 i 顆）或 block 層級（第 i 塊到第 i 顆）。
  • Mirroring / shadowing (RAID 1) keeps a duplicate of each disk. Striped mirrors (RAID 1+0) or mirrored stripes (RAID 0+1) give high performance and high reliability. Block-interleaved parity (RAID 4, 5, 6) uses much less redundancy.鏡像（RAID 1）每顆磁碟都有複本。RAID 1+0（先鏡像再 striping）或 RAID 0+1（先 striping 再鏡像）兼顧高效能與高可靠性。區塊交錯同位（RAID 4、5、6）冗餘少很多。
  • RAID inside a storage array can still fail if the array fails, so automatic replication between arrays is common. A few hot-spare disks are left unallocated to replace a failed disk automatically and have data rebuilt onto them.儲存陣列本身壞掉時裡面的 RAID 也救不了，所以陣列之間常做自動複製。保留幾顆 hot spare，壞一顆時自動頂上並重建資料。

Other Features and Extensions其他功能與延伸

  • Snapshot: a view of the file system before a set of changes take place (at a point in time). Replication: automatic duplication of writes between separate sites, for redundancy and disaster recovery; synchronous or asynchronous. Hot spare: an unused disk automatically used to replace a failed disk and rebuild the RAID set, decreasing the mean time to repair.Snapshot：某一時間點、一批修改發生前的檔案系統樣子。Replication：在不同地點之間自動複製寫入，做冗餘與災難復原；可同步或非同步。Hot spare：閒置磁碟，有磁碟壞掉時自動頂上並重建 RAID，降低平均修復時間。
  • RAID alone does not prevent or detect data corruption or other errors, just disk failures. Solaris ZFS adds checksums of all data and metadata, kept with the pointer to the object, so it can detect and correct corruption. ZFS also removes volumes and partitions: disks are allocated in pools, and file systems in a pool share it, using and releasing space like malloc() and free().RAID 本身不能防止或偵測資料損毀等錯誤，只能應付磁碟故障。Solaris ZFS 為所有資料與 metadata 加 checksum，跟指向物件的指標存在一起，能偵測並修正損毀。ZFS 也不用 volume 和 partition：磁碟放進儲存池，池裡的檔案系統共用空間，像 malloc()、free() 一樣取用與釋放。

8.6 Stable-Storage Implementation ★★穩定儲存的實作

  • The write-ahead log scheme requires stable storage: storage whose data is never lost (due to failure, etc.).write-ahead log 需要穩定儲存：資料永遠不會因故障等原因遺失。
  • To implement it: replicate information on more than one nonvolatile storage medium with independent failure modes, and update information in a controlled manner so the stable data can be recovered after any failure during transfer or recovery.實作：把資料複製在多個故障模式互相獨立的非揮發性媒介上，並以受控的方式更新，任何傳輸或恢復中的故障之後都能把資料救回來。
Outcome of a disk write寫入的結果Meaning意思
Successful completionThe data were written correctly on disk.資料正確寫到磁碟上。
Partial failureA failure occurred in the midst of the transfer: only some sectors were written, and the sector being written may be corrupted.傳到一半故障：只寫了部分 sector，正在寫的那個可能已損壞。
Total failureThe failure occurred before the write started, so the previous data on disk remain intact.還沒開始寫就故障，磁碟上的舊資料完好。
ANSWER: Two-copy writeThe system maintains 2 physical blocks per logical block: (1) write to the 1st physical block; (2) when that succeeds, write to the 2nd; (3) declare the operation complete only after the second write completes successfully. If a failure occurs during a block write, the recovery procedure restores the block to a consistent state. Systems frequently use NVRAM as one of the physical copies to accelerate this.
中文每個邏輯區塊維護兩個實體區塊：(1) 先寫第一個；(2) 成功後再寫第二個；(3) 第二個也寫成功才宣告完成。寫到一半故障時，恢復程序會把區塊還原成一致的狀態。常用 NVRAM 當其中一份來加速。
Chapter summarySummary 本章總結
  • Disk access = seek time + rotational latency + transfer time (+ controller overhead); average latency is half a rotation. SSDs have no seek or rotational latency; tape is cheap and slow (backup).磁碟存取＝seek time＋旋轉延遲＋傳輸時間（＋控制器負擔）；平均旋轉延遲是半圈。SSD 沒有 seek 和旋轉延遲；磁帶便宜但慢（拿來備份）。
  • A disk is a 1-D array of logical blocks mapped sequentially from the outermost cylinder inward.磁碟是一維邏輯區塊陣列，從最外圈 cylinder 往內依序對應。
  • Attachment: host-attached (SCSI, FC), storage arrays, NAS (files over the IP network, NFS / CIFS, iSCSI) and SAN (storage arrays on Fibre Channel switches).連接：host-attached（SCSI、FC）、儲存陣列、NAS（透過 IP 網路分享檔案，NFS／CIFS、iSCSI）、SAN（儲存陣列接在 FC 交換器上）。
  • Disk scheduling minimizes seek distance: FCFS, SSTF (can starve), SCAN (elevator), C-SCAN (uniform wait), LOOK / C-LOOK (turn at the last request). SSTF or LOOK is a reasonable default.磁碟排程要讓 seek 距離最小：FCFS、SSTF（會飢餓）、SCAN（電梯）、C-SCAN（等待平均）、LOOK／C-LOOK（走到最後一個要求就回頭）。預設用 SSTF 或 LOOK。
  • RAID improves performance (striping) and reliability (mirroring, parity): levels 0 to 6, 0+1 and 1+0; hot spares, replication, snapshots; ZFS adds checksums.RAID 用 striping 提升效能、用鏡像與同位提升可靠性：等級 0 到 6、0+1、1+0；還有 hot spare、replication、snapshot；ZFS 加了 checksum。
  • Stable storage: keep two physical copies and write them one after the other; the write is complete only when both succeed.穩定儲存：存兩份實體複本、一份寫完再寫另一份；兩份都成功才算完成。
Common trap易錯點
  • Average rotational latency is half a rotation: 7200 RPM → 8.33 ms per turn → 4.17 ms.平均旋轉延遲是半圈：7200 RPM → 一圈 8.33 ms → 4.17 ms。
  • SCAN goes to the end of the disk before turning; LOOK turns at the last request. Always state the direction.SCAN 要走到磁碟盡頭才回頭；LOOK 在最後一個要求就回頭。一定要寫方向。
  • C-SCAN and C-LOOK do not serve requests on the return trip; say whether you count the return jump.C-SCAN、C-LOOK 回程不服務；要寫清楚有沒有把回程算進去。
  • SSTF may starve far requests and is not optimal.SSTF 可能讓遠的要求飢餓，而且不是最佳解。
  • RAID 0 has no redundancy; RAID 4 keeps parity on one disk, RAID 5 spreads it; RAID 6 survives two failures.RAID 0 沒有冗餘；RAID 4 同位放一顆、RAID 5 分散放；RAID 6 可壞兩顆。
  • RAID protects against disk failure, not data corruption (that is what ZFS checksums are for). NAS shares files, SAN shares blocks.RAID 防的是磁碟故障，不是資料損毀（那要靠 ZFS checksum）。NAS 分享檔案、SAN 分享區塊。
